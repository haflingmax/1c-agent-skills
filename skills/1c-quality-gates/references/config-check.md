# Проверка конфигурации: двадцать четыре режима, включены два

**Ищут по словам:** проверка конфигурации, синтаксический контроль,
`/CheckConfig`, `/CheckModules`, расширенная проверка, поиск неиспользуемых
процедур, пустые обработчики, поиск модальности, синхронные вызовы, режимы
проверки, инструкции препроцессора, «возможно ошибочные», настройка проверки.

Источники: руководство разработчика §35.22 «Выполнение централизованной
проверки конфигурации» и §35.2.1.8 «Синтаксический контроль»; глава 39
(§39.2.3.2 — настройки конфигуратора и умолчания); руководство
администратора, приложение 7 «Параметры командной строки» (`/CheckConfig`,
`/CheckModules`).

Правило про то, что зелёный ответ ничего не доказывает, стоит **в теле
навыка**; здесь разбор механизма целиком.

## Что этот прибор делает

Проверка компилирует модули в заданном окружении: «Любой прикладной код
в системе «1С:Предприятие» выполняется в некотором окружении. Это окружение
характеризуется некоторым набором определенных инструкций препроцессора…
и набором доступных объектов. Соответственно, при выполнении проверки
конфигуратор определяет инструкции препроцессора для каждого отмеченного
пункта и выполняет проверку».

Отсюда главное свойство прибора: **он проверяет ровно те окружения, флажки
которых отмечены.** Неотмеченное окружение не проверено, и в отчёте этого
не видно.

## Умолчание: два режима из двадцати четырёх

«По умолчанию конфигуратор устанавливается следующие режимы проверок:
● Управляемое приложение: Тонкий клиент, Сервер. ● Мобильное приложение:
Тонкий клиент, Мобильный клиент, Сервер, Мобильное приложение ‑ клиент.
● Обычное приложение: Толстый клиент (обычное приложение)» (§39.2.3.2;
орфография источника сохранена).

Для обычной управляемой конфигурации это **два включённых режима**, а всего
их в диалоге двадцать четыре — по числу строк «Параметр команды
/CheckConfig» в §35.22. То есть по умолчанию не проверяются веб-клиент,
внешнее соединение, толстый клиент и все логические проверки.

**И набор помнится:** «После изменения значения параметра Редактирование
конфигурации для режимов запуска… конфигуратор восстановит набор режимов
проверки, который был при последнем сохранении настроек (для выбранного
режима запуска)».

**Настройки живут под именем:** «Выбранную совокупность настроек можно
сохранить для дальнейшего использования… Для использования прежней настройки
достаточно выбрать имя настройки».

Практическое следствие для приёмки чужой работы: **«проверка выполнялась»
не ответ.** Ответ — какая именованная настройка прогонялась и какие флажки
в ней стояли.

## Два окна с разными наборами

«● Группа проверок, доступная для принудительной и автоматической проверки
при редактировании конфигурации. Эти режимы доступны для выбора на закладке
Модули ‑ Проверка диалога настройки параметров конфигуратора… ● Весь список
проверок, который можно вызвать при централизованной проверке конфигурации».

Флажки «Сервис ‑ Параметры ‑ Модули ‑ Проверка» и флажки «Проверка
конфигурации» — **разные наборы**. Настройка одного окна ничего не говорит
о другом, и «у меня проверка включена» может означать любое из двух.

## Чего проверка не видит

Пять границ, названных источником прямо.

**Серверный код проверяется частично.** «если проверяется клиентское
приложение в клиент-серверном варианте, то на стороне клиента проверяется
весь прикладной код, а на стороне сервера ‑ только те общие модули, которые
доступны для вызова из клиентской части приложения». Серверный модуль,
не вызываемый с клиента, требует отдельного прогона с флажком «Сервер».

**Закрытые модули дают ложную тревогу.** «В том случае, если в проверяемом
приложении существует общий модуль, поставляемый без исходных текстов,
то при проверке конфигурации все вызовы методов этого общего модуля будут
отмечаться как возможно ошибочные». «Возможно ошибочные» — признание, что
проверяльщик не видел тела метода, а не найденная ошибка.

**Расширенная проверка молчит о месте.** «Сообщения, которые формируются
в результате расширенной проверки модулей, не содержат номеров строк
с обнаруженными проблемами», и сама она работает «для ограниченного набора
типов» — состав набора источник не раскрывает. Разобрать её вывод машинно
по строкам нельзя.

**Свойство конфигурации молча вычитает модули.** У толстого клиента: «Если
свойство конфигурации Использовать управляемые формы в обычном приложении
имеет значение Ложь, то модули управляемых форм и модули команд
не проверяются при выборе этого теста».

**Состав самого диалога зависит от режима редактирования.** «Если параметр
Редактирование конфигурации для режимов запуска… имеет значение Управляемое
приложение и обычное приложение, то в диалоге добавляются следующие
параметры: ● Толстый клиент (обычное приложение); ● Толстый клиент (обычное
приложение, вариант клиент-сервер)». При значении «Управляемое приложение»
этих флажков в окне нет вовсе, и ничем это не отмечено.

**И шестая граница — не из этого параграфа, а из живого прогона набора:**
текст запроса внутри строкового литерала проверка не видит. Прогон
и его контрольный опыт — у соседа `1c-queries`.

## Флажки, которые включаются только парой

**Модальность и синхронные вызовы недоступны без расширенной проверки:**
«Данный флажок становится доступным только в том случае, если включена
расширенная проверка конфигурации», и в командной строке то же —
`‑CheckUseModality`, «но только совместно с параметром
‑ExtendedModulesCheck».

Пока расширенная проверка выключена, отсутствие сообщений о модальности
означает не «модальности нет», а «её не искали».

**А свойство конфигурации на эту проверку не влияет:** «Свойство
конфигурации Режим использования модальности не влияет на работу механизма
проверки. При включении данного флажка ошибки будут выдаваться и в том
случае, если свойство Режим использование модальности установлено
в значение Использовать или Использовать с предупреждением».

## Логические проверки: что именно они считают ошибкой

**Поиск неиспользуемых процедур ищет только локальные:** «Поиск локальных
(не экспортируемых) процедур и функций, на которые отсутствуют ссылки».
Экспортные не ищутся вовсе.

**И признак «используется» слабее, чем кажется:** «Процедура или функция
модуля формы будет считаться используемой, если ее имя встречается в виде
"ИмяПроцедуры" (включая кавычки), т. е. является параметром какого-либо
метода». Строка `"МояПроцедура"` в сообщении пользователю снимает подозрение
с мёртвого кода.

**Пустые обработчики — проверка производительности, а не корректности:**
«Поиск назначенных обработчиков событий, в которых не выполняется никаких
действий. Существование таких обработчиков может привести к падению
производительности системы».

**Проверка существования обработчиков** закрывает то, о чём платформа
в рабочем режиме молчит: «Проверка существования обработчиков событий
интерфейсов, форм, элементов управления, элементов карт маршрута».

## Соответствие «флажок ↔ ключ»

Каждый режим диалога имеет свой параметр `/CheckConfig`. Общие:
`‑ConfigLogIntegrity` (логическая целостность), `‑IncorrectReferences`
(некорректные ссылки). Синтаксический контроль: `‑ThinClient`, `‑WebClient`,
`‑MobileClient`, `‑MobileClientStandalone`, `‑Server`, `‑ExternalConnection`,
`‑ExternalConnectionServer`, `‑MobileAppClient`, `‑MobileAppServer`,
`‑ThickClientManagedApplication`, `‑ThickClientServerManagedApplication`,
`‑ThickClientOrdinaryApplication`,
`‑ThickClientServerOrdinaryApplication`, `‑DistributiveModules`. Логические:
`‑UnreferenceProcedures`, `‑HandlersExistence`, `‑EmptyHandlers`,
`‑ExtendedModulesCheck`, `‑CheckUseModality`, `‑CheckUseSynchronousCalls`.
Мобильные: `‑UnsupportedFunctional`, `‑MobileClientDigiSign`.

Перечень ключей как справочник — у соседа `1c-build-and-db`
(`scripts/cli-keys.json`); здесь важно другое: **флажков ровно столько же,
сколько ключей, и отмечены из них по умолчанию два.**

## Ещё три вещи про сам диалог

**Отчёта файлом он не даёт:** «Все сообщения об ошибках выдаются в окно
сообщений». Машинно разбирается только вывод командной строки.

**При подключённом хранилище нужен захват корня:** «При проверке
конфигурации, подключенной к хранилищу, во избежание ошибок, связанных
с информацией о метаданных, рекомендуется захватить корневой объект
конфигурации». Без захвата возможны ошибки **прибора**, с виду неотличимые
от ошибок конфигурации.

**Прерывание срабатывает не сразу:** «В начальной стадии проверки прерывание
может быть обработано с задержкой».

## Чего в §35.22 нет

- **состава «ограниченного набора типов»** расширенной проверки — сказано
  дважды «для ограниченного набора» и ни разу, какого;
- **признака успеха для конвейера:** диалог даёт окно сообщений, а не код
  возврата; машинный ответ ищется в командной строке;
- **что делать с сообщениями «возможно ошибочные»** на чужой конфигурации
  с закрытыми модулями: источник называет причину, но не способ отделить
  их от настоящих.

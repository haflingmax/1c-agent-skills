# Сравнение и объединение конфигураций

**Ищут по словам:** взять из загружаемой конфигурации, объединить
с приоритетом, режим объединения, приоритет конфигурации, отчёт о сравнении,
соответствие объектов, удаление объектов основной конфигурации, объединение
модулей, объединение макетов, предопределённые при объединении, внешняя
программа сравнения, трёхстороннее объединение.

Источники: руководство разработчика, глава 36 целиком; §39.2.6 «Сравнение
и объединение» (настройки конфигуратора); методичка 2327.

Правила про то, что объединение делает не то, что обещает, стоят **в теле
навыка**; здесь механика целиком.

Сравнение **расширений** между собой разобрано у соседа `1c-extensions`
(справочник о сравнении и хранилище) — здесь только конфигурации.

## Соответствие объектов: по имени, кроме случаев, когда не по имени

**Обычное правило:** «При автоматической установке соответствия программа
анализирует объекты конфигураций, имеющие одинаковые имена» (§36.2).

**Исключение в пользу идентификатора:** «Если имена различны, а внутренние
идентификаторы совпадают, то для таких объектов автоматически устанавливается
соотве…» — то есть переименование пару не рвёт, а смена идентификатора рвёт.

**У страниц формы признаков три подряд:** «Сначала производится анализ
по именам; затем для страниц, имеющих разные имена, производят анализ
по заголовкам страни…», а «Для страниц, у которых все три свойства (Внутренний
идентификатор, Заголовок и Картинка) пустые, будет производиться п…»
сопоставление по порядку.

**А предопределённые — только по идентификатору** (§36.10.4), и при
столкновении имён «элементу из неприоритетной конфигурации будет добавлен
числовой суффикс». Правило стоит в теле; здесь важно, что это **исключение
из общего правила соответствия по имени**, и потому его не ждут.

## Умолчания окна сравнения

**Конфигурации считаются чужими:** «По умолчанию установлен режим сравнения
различных конфигураций (не связанных друг с другом)» (§36.6.1). Для обновления
это надо менять — иначе история изменений не пристёгивается ни к одной колонке.

**Показывается не всё:** «При открытии окна Объединение конфигураций установлен
фильтр Показывать отличия в конфигурациях» (§36.5).

**Новые объекты приходят с чужими идентификаторами:** «По умолчанию при
объединении конфигурации объекты, отсутствующие в основной конфигурации,
добавляются в нее с теми идентификаторами, которые существую…» в загружаемой
(§36.6.3).

**Смена настройки перезапускает сравнение:** «При нажатии кнопки ОК
производится повторное сравнение с учетом выбранной настройки» — уже
расставленные вручную режимы после этого надо проверять.

## Дважды изменённое свойство: как его вообще найти

Дважды изменённое — то, что «и пользователь, и поставщик меняли одно и то же
свойство», и по нему «разумных предположений автоматически сделать невозможно».
Именно эти свойства решаются умолчанием, если их не найти.

**Находятся они двумя способами, и оба надо знать.** Пассивно: «Все подобные
свойства в дереве объединения показываются жирным шрифтом» — то есть их надо
высматривать среди прочих. Активно: «в настройке фильтра просмотра можно
указать флажок Показывать только дважды измененные свойства, и в дереве
объединения будут показываться только те свойства, которые требуют ручной
установки правил объединения» (методичка про поставку и поддержку).

Стандарт про разветвлённую разработку описывает тот же приём как шаг
технологии: «нажать кнопку "Фильтр" и установить флажок Показывать только
дважды измененные свойства». И добавляет границу применимости: «На эти
объекты нужно обратить внимание при объединении, остальные изменения можно
объединять без проверки».

Из пакетного режима фильтра нет — там только выгрузка списка в файл
(см. `outside-the-configurator.md`).

## Удаление объектов основной конфигурации

Самое дорогое умолчание главы. «При выполнении любого объединения конфигураций
существует возможность удаления объектов основной конфигурации. По умолчанию
эта возможность включена т…» — только для обновления с конфигурацией
поставщика (§36.6.2).

**Признак, по которому объект попадает под нож, обратный ожидаемому:** «Если
пользователь изменял объект поставщика по сравнению с предыдущей версией
конфигурации поставщика, то объект по умолчанию **не помечается** на удалени…».
То есть защищён тот, кого вы правили, а нетронутый — помечается.

**И один стопор, который не обходится:** «При обнаружении неразрешимых ссылок
на удаляемый объект будет выдано окно показа таких ссылок, но, в отличие
от неразрешимых ссылок, образующихся в ре…» обычном объединении, продолжить
нельзя.

## Два режима объединения и что каждый делает

**«Взять из загружаемой конфигурации» — полная замена:** «объект конфигурации
будет добавлен, если он новый, или замещен, если он измененный. Причем
переносится вся структура …» объекта, модули, описания, формы (§36.10.1).

**«Объединить с приоритетом» — сохранение старого:** «из загружаемой
конфигурации необходимо взять только новое и максимально сохр…» существующее.

**Режим есть не у всего:** «Для некоторых объектов (реквизитов объектов) выбор
режима объединения может отсутствовать или иметь ограниченный выбор вариантов
объединения».

## Как объединяются тексты модулей (§36.10.2)

Ключевое: объединение текста **ничего не удаляет**.

- при приоритете основной конфигурации новый код поставщика «Добавляется в виде
  комментариев из загружаемой конфигурации, а то, что было в основной, остается
  неизменным»;
- удалённое поставщиком — «Удаленное (имеется в основной конфигурации,
  отсутствует в загружаемой)» — у вас остаётся;
- изменённое «Превращается в комментарии».

Модуль после такого объединения компилируется и работает по-старому, а новое
лежит в нём комментарием. Внешне это выглядит как успешное обновление.

**Внешняя программа отменяет всю эту таблицу:** «то результат объединения
зависит от используемой внешней программы».

## Формы (§36.10.3)

**Различия не показываются:** «При объединении управляемых форм
не поддерживается графическое отображение отличий в окне Объединение
конфигураций, но возможно отображение результато…» в отчёте о сравнении.

**Сопоставление внутри формы — по именам:** «тексты модулей сравниваются
по именам процедур; элементы формы сравниваются по типу элемента и его имени;
параметры формы сравниваются по имени; коман…» — и далее по списку.

**Совпавший элемент замещается целиком:** «Совпадающие элементы (по именам)
в основной форме будут заменены (заменяются свойства, размеры и расположение),
если выбран приоритет загружаемой конф…».

**Форму и её модуль можно развести по режимам:** «Режим объединения формы можно
задавать как в целом для всей формы (сама форма и модуль формы)… так и отдельно
для фо…» — но не для всякой формы.

## Что объединяется мимо приоритета (§36.10.6, §36.10.7)

Приоритет — не универсальный переключатель. Мимо него идут:

- **составные типы**: «результирующий тип будет содержать типы из обеих
  конфигураций»;
- **длина строки** — берётся максимальная;
- **составы**: планов обмена, подсистем, функциональных опций — «образуется
  объединением составов».

Практическое следствие: тип или объект, намеренно убранный из состава,
возвращается при обновлении независимо от того, какой приоритет вы выбрали.

## Макеты (§36.10.8)

«результирующий макет будет состоять из макета основной и загружаемой
конфигураций, разделенных строкой, имеющей желтый фон… Окончательное
объединение следует провести вручную после сравнения».

**И одно различие, которое окно не показывает:** «Сравнение табличных
документов производится по ячейкам. Если ячейки различны (любые свойства,
**кроме свойства Параметр расшифровки**), то различие показывается цветом»
(§36.12). Две ячейки, отличающиеся только расшифровкой, выглядят одинаковыми.

## Настройки конфигуратора умеют переписать вашу расстановку (§39.2.6)

Правило подмены названо источником прямо: «Если в данном свойстве указано
значение Не используется … все режимы объединения, где было указано
использование внешней программы, заменяются на режим Взять из новой
конфигурации поставщика (если открыто окно обновления основной конфигурации)».

**И симметричная ловушка:** при указанной внешней программе и флажке
«Устанавливать по умолчанию» сохранение настроек само назначает режим
«Объединить с помощью внешней программы» там, где его не выбирали.

Обе подмены происходят при сохранении диалога параметров — то есть в момент,
который не выглядит частью обновления.

## Настройки объединения: файл и автосохранение (§36.5)

**Загрузка настроек стирает набранное руками:** «Загрузить настройки… ‑
настройки окна сбрасываются к настройкам по умолчанию, а затем выполняется
загрузка настроек об…»; добавление настроек — не стирает.

**Файл настроек — это разница, а не снимок:** «Сохраняются только те настройки
объединения, которые отличаются от настроек по умолчанию». Перенос файла в базу
с другими умолчаниями даст другой результат.

**Настройки могут сохраниться сами:** «Флажок Сохранять настройки автоматически
управляет автоматическим сохранением настроек окна сравнения/объединения
пере…» объединением.

**И один прямой запрет источника:** «При открытом окне сравнения и объединения
конфигураций не рекомендуется выполнять длительные операции по работе
с конф…».

## Чего в главе 36 нет

- **что делать после объединения** с конфигурацией базы данных — глава
  заканчивается на объединении, а изменения к этому моменту в базе ещё
  не применены;
- как сравнить конфигурацию с расширением — прямо запрещено (см. соседа
  `1c-extensions`);
- чем отличается результат объединения одной и той же пары в разных версиях
  платформы.

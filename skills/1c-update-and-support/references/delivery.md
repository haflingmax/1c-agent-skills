# Поставка: файлы, комплект, тексты модулей

**Ищут по словам:** файл поставки, файл обновления, `cf`, `cfu`, комплект
поставки, дистрибутив, настройка поставки, создание файлов поставки, поставщик
и версия конфигурации, исходные тексты модулей в поставке, обратное обновление,
`1cv8.efd`, каталог шаблонов.

Источники: руководство разработчика, §38.1 «Общая информация» и §38.2
«Поставка конфигурации»; методички серии 2294 и 3271.

Этот справочник — про сторону поставщика. Тому, кто обновляет чужую базу, он
нужен ради одного: понять, **что именно ему прислали** и что этот файл умеет.

## Три разные вещи с похожими названиями (§38.1)

- **Полная поставка** — «файл конфигурации формата \*.cf, сформированный
  специальным образом»;
- **поставка обновлений** — «файл обновлений формата \*.cfu»;
- **комплект поставки** — «дистрибутив, в состав которого входит программа
  установки для операционных систем Windows (файл setup.e…», Linux и macOS,
  «а также файлы поставки, сжатые в специальный архив (файл 1cv8.efd)».

**Оговорка «сформированный специальным образом» несёт всю нагрузку:** обычная
выгрузка конфигурации в `.cf` файлом поставки не является. Методичка говорит
это прямо: «Файл, подготовленный командой Конфигурация ‑ Сохранить
конфигурацию в файл , в качестве конфигурации поставщика использовать нельз…».

**А поддержка — это свойство, а не договор:** «Поддержка конфигурации
заключается в способности конфигурации быть обновляемой средствами
конфигуратора с использованием файлов поставки. На…значение механизма
поддержки — в защите логической целостности конфигурации».

## `cf` против `cfu`

**`cfu` привязан к версиям, для которых сделан:** файлы обновления
«не поддерживают обновления не только для более ранних версий конфигурации,
чем они предназначены, но…» и для более поздних. Причина названа: обратные
правки поставщика — «Если позволить использовать такой файл для обновления
версии "3", то у пользователя окажется неправильная, увеличенная длина строк…».

**`cf` обновляет с любой версии, включая движение вниз:** «Обновление
конфигурации с помощью файлов (cf) может выполняться с любой версии (в том
числе и более новой, при необходимости отказ…» от новой версии.

Отсюда практическое: если прислали `cfu`, а версия базы не та, для которой он
собран, — обновление не пойдёт, и это не поломка, а устройство файла.

## Что нужно, чтобы поставку вообще собрать (§38.2.2)

**Два свойства конфигурации обязательны:** «Предварительно в категории свойств
Разработка должны быть указаны свойства Поставщик и Версия».

**Модифицированную конфигурацию не отдают:** «Если конфигурация или база данных
модифицирована, то конфигуратор просит произвести сохранение конфигурации
и обновить конфигурацию базы дан…».

**Номер версии — структура, а не строка:** «В списке шаблонов и обновлений
конфигураций конфигурации сортируются по номерам версий с учетом структуры
номера».

**Файл обновления тянет за собой прежние:** «Если флажок Создать файл
обновления конфигурации установлен, то требуется включить в файл обновления
прежние обновления».

**И кодировка комплекта задана жёстко:** «Текстовые файлы комплекта поставки
нужно подготавливать в кодировке UTF-8».

## Тексты модулей: что теряется у клиента (§38.2.1)

Поставщик вправе не отдавать исходные тексты: «В этом случае функциональность
не нарушается, но текст модуля недоступен для просмотра».

**Но не для всех модулей.** Источник даёт закрытый перечень тех, у кого
исходники исключить нельзя: «Не поддерживается исключение исходных текстов для
следующих модулей» — модуль управляемого приложения, модули форм, модули
команд, модули с директивами препроцессора и клиентские общие модули
управляемого режима.

**Снятие флажка у корня бьёт шире, чем кажется:** «Если флажок Включать
в поставку исходный текст модулей объекта снят для корневого элемента
конфигурации, то без исходных текстов будут поста…» сразу несколько модулей
конфигурации.

Для того, кто обновляет: закрытые тексты означают, что сравнение по модулю
покажет различие, а разобраться в нём будет нечем.

## Флажок, отнимающий откат

«Файл поставки может использоваться для обновления» стоит по умолчанию,
и его сброс — решение с последствиями: «Сброс данного флажка отменяет последнюю
возможность» выполнить «обратное обновление» с более поздней версии.

Источник называет и законный случай сброса: «Снять флажок нужно в том случае,
когда предполагается использовать полученный файл поставки как промежуточный,
когда требуется произвести ря…» действий.

## Правила поставки задаются не везде

«В иерархическом списке объектов конфигурации доступны **только объекты первого
уровня**» (§38.2.1). Реквизиту, форме или макету собственного правила
поставщика не назначить — они наследуют правило владельца.

Разбор самих правил — в `support-rules.md`.

## Чего в §38.1 и §38.2 нет

- **как отличить файл поставки от обычной выгрузки** до попытки загрузки:
  «сформированный специальным образом» — единственное, что сказано;
- что происходит, если у файла поставки и базы разные редакции платформы;
- как проверить целостность или происхождение присланного файла — источник
  ограничивается требованием доверять источнику (§38.3.4).

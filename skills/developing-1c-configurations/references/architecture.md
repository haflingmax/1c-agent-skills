# Устройство навыка: почему разделы такие

Документ отвечает на один вопрос: по какому признаку разрезаны поднавыки и почему именно так.
Он нужен при добавлении нового поднавыка — чтобы новый кусок лёг в раскладку, а не рядом с ней.

## Признак разреза

Разделы разрезаны **по области знания разработчика**, а не по типу файла и не по команде.

Это осознанный выбор против того, как устроены оба известных набора навыков по 1С: там разрез
идёт по артефакту и операции (`meta-compile`, `meta-decompile`, `meta-validate`,
`meta-info`, `meta-edit`, `meta-remove` — шесть навыков на один тип файла). Такой разрез
удобен человеку, который зовёт команду по имени, и плох для агента, который выбирает навык
сам по описанию: шесть описаний отличаются одним глаголом, и выбрать между ними по смыслу
задачи невозможно.

У нас один раздел отвечает на вопрос «что я сейчас делаю» — правлю форму, пишу запрос,
настраиваю права, — а операции внутри раздела остаются операциями, а не отдельными навыками.

## Соответствие разделам ИТС

Раскладка сверена с системой стандартов 1С (`its.1c.ru/db/v8std`). Соответствие
неполное намеренно: часть стандартов ИТС — про организацию работы команды и про
процессы, а не про то, что делает агент над исходниками.

| Раздел навыка | Область ИТС |
|---|---|
| `1c-code-conventions` | соглашения по написанию кода, оформление модулей, тексты |
| `1c-metadata-objects` | создание и изменение объектов метаданных |
| `1c-managed-forms` | формы |
| `1c-queries` | реализация обработки данных |
| `1c-access-rights` | настройка прав доступа к данным, общие вопросы безопасности |
| `1c-client-server` | клиент-серверное взаимодействие |
| `1c-extensions` | разработка и внедрение расширений, совместимость расширений |
| `1c-reports-and-layouts` | отчёты, печатные формы |
| `1c-integrations` | обмен данными, сервисы |
| `1c-build-and-db` | вне ИТС: работа с платформой и поставками |
| `1c-update-and-support` | организация работы конфигурации, поддержка |
| `1c-quality-gates` | вне ИТС: проверки и тестирование |
| `1c-publish-and-operate` | вне ИТС: эксплуатация |

**Не закрыто и требует сверки по подписке ИТС:** точный перечень подразделов v8std. Публично
доступное оглавление отдаёт только верхний уровень, поэтому соответствие выше построено по
названиям областей, а не по полному дереву стандартов. До сверки считать таблицу черновиком.

**Сознательно вне охвата:** разработка для мобильной платформы, облачные технологии,
стандарты для платформы 8.2. Первое — отдельная платформа, второе и третье — не наш случай.

## Правила для новых поднавыков

1. **Один раздел — одна область знания.** Если новый кусок отвечает на вопрос «чем я работаю»,
   а не «что я делаю», он не раздел, а часть существующего.
2. **Описание в третьем лице и с признаком применения.** «Применяется, когда…», а не
   «Используй, когда…». Это требование Anthropic: описание попадает в системную подсказку, и
   разнобой лица ломает выбор навыка.
3. **Имя: только строчные латинские буквы, цифры и дефисы.** Не длиннее 64 знаков. Слова
   `claude` и `anthropic` в имени запрещены спецификацией.
4. **Тело до 500 строк и до 5 тысяч токенов.** Что не влезло — в `references/`, ссылкой на
   один уровень вниз, не глубже.
5. **Пути через прямую косую**, даже под Windows.
6. **Механику — в скрипт, суждение — в текст.** Если операция однозначна (сгенерировать XML по
   описанию), её место в скрипте: детерминированно, дёшево по контексту, проверяемо. Текст
   навыка тратится только на то, где нужно решение.
7. **Каждый раздел обязан иметь проверку.** Навык, после которого нельзя убедиться в
   правильности результата, не готов.

## Что намеренно не сделано

**Нет отдельных навыков под каждую операцию.** Сознательно: см. «Признак разреза».

**Нет поля `argument-hint` во фронтматтере.** Оба исходных набора ставят его у 85–100% навыков.
Это поле слэш-команд Claude Code, а не спецификации навыков; в Kilo команды живут отдельно, в
каталоге `command/`. Поле не вредит, но приучает писать навык как команду — а он должен
находиться сам.

**Нет привязки к одной среде.** Навык не зависит от переменных вида `${CLAUDE_SKILL_DIR}`:
пути внутри навыка относительные, от каталога самого навыка.

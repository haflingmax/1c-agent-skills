# Две раскладки исходников: выгрузка XML и проект EDT

Одна и та же конфигурация лежит на диске двумя разными способами. Спутать их — значит
править файлы, которые ни во что не соберутся.

## Как отличить

| Признак | Выгрузка конфигуратора | Проект 1С:EDT |
|---|---|---|
| Корневой файл | `Configuration.xml` | `.project`, `DT-INF/` |
| Где объекты | `Catalogs/Номенклатура.xml` | `src/Catalogs/Номенклатура/Номенклатура.mdo` |
| Расширение описания | `.xml` | `.mdo` |
| Модуль | `Catalogs/Номенклатура/Ext/ManagerModule.bsl` | `src/Catalogs/Номенклатура/ManagerModule.bsl` |
| Форма | один `Form.xml` внутри `Ext/` | каталог формы с `Form.form` |
| Служебный файл версий | `ConfigDumpInfo.xml` | отсутствует |

Признак, по которому не ошибёшься: **наличие `Configuration.xml` в корне**. Если он есть —
это выгрузка конфигуратора. Если вместо него `.project` и каталог `src` — это EDT.

## Почему нельзя работать с EDT приёмами для XML

Формат `.mdo` — не переименованный XML выгрузки. Отличается состав элементов, порядок,
способ ссылаться на другие объекты и раскладка форм. Генератор XML, применённый к проекту
EDT, создаст файлы, которые EDT не подхватит, а конфигуратор не увидит, потому что для него
нет `Configuration.xml`.

## Что делать, если пришёл проект EDT

Есть три пути, в порядке предпочтения.

1. **Выгрузить из EDT в формат конфигуратора** и работать с выгрузкой. Делается средствами
   самого EDT (экспорт конфигурации) либо командой `ring edt workspace export`. Обратно —
   импортом. Это самый надёжный путь: вся остальная оснастка рассчитана на выгрузку.
2. **Работать только с модулями.** Файлы `.bsl` в обоих форматах — обычный встроенный язык, и
   правка кода в проекте EDT безопасна. Соглашения из раздела кода применимы полностью.
3. **Править `.mdo` вручную** — только когда первые два пути закрыты, и с обязательной
   проверкой открытием проекта в EDT.

## Чего делать нельзя

Не превращай одну раскладку в другую переименованием файлов и не смешивай их в одном дереве.
Конфигурация, где рядом лежат `Configuration.xml` и `src/`, — это либо незавершённая
конвертация, либо два разных проекта в одной папке; прежде чем менять что-либо, выясни, какой
из них рабочий.

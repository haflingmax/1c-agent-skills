# Наборы данных и связи между ними

**Ищут по словам:** набор данных, связь наборов, объединение, вложенный набор,
выражение связи, обход, поле-итог, вычисляемое поле, иерархический набор.

Источник — руководство разработчика 8.3.27, глава 10, параграфы 10.3.1
(составные части схемы), 10.3.2 (работа с несколькими наборами) и 10.9
(иерархия). **Строки «Область применения» здесь нет** и быть не может:
это не система стандартов, а описание механизма. Нумерации у правил §10.3.2
тоже нет — там сплошная проза на примере наборов ПрайсЛист, Остатки, Продажи,
поэтому адреса ниже даны по положению абзаца относительно рисунков. Так же
они выписаны и в теле навыка.

Два правила §10.3.2 стоят **в теле навыка** — про тип связи и про источник
одноимённого поля. Здесь остальное.

## Связи наборов: чего в схеме не видно

**Типа связи в схеме нет вовсе.** «В схеме компоновки данных нет указания типа
связи. Все связи считаются левыми внешними соединениями. То есть запись
родительского набора данных будет использоваться в компоновке даже в том
случае, если для нее не найдены записи в зависимом наборе».

Оговорка стоит сразу следом и объясняет, где тип всё-таки появляется:
«В макете компоновки данных… возможно указание типа связи. **Тип связи
генерируется компоновщиком макета в зависимости от накладываемых глобальных
отборов**».

**И вот как он генерируется** (абзац перед рис. 433): «Если на поле набора
данных, являющегося зависимым, накладывается глобальный отбор, генерируемые
связи в макете компоновки данных от этого набора данных до всех его
родительских наборов (**вплоть до начала иерархии наборов данных**) будут
иметь тип Внутренняя. Это означает, что записи родительского набора данных
будут участвовать в компоновке **только в том случае, если будут найдены
записи в зависимых наборах данных**».

Это и есть то, ради чего правило стоит в теле: отбор ставят на одном наборе,
а соединение меняется по всей цепочке вверх.

## Порции по 1000 записей

«Если набор данных зависит от некоторого набора и в связи указана возможность
использования **списка параметров**, данные из зависимого набора данных будут
получаться **порциями по 1000 записей**. В случае, если использование списка
параметров в связи не разрешено, записи будут получаться **по одной**».

Единственное численное значение раздела. Чем «по одной» оборачивается
по числу обращений к базе, источник не пишет; порядок величины очевиден
из самого слова.

## Что нельзя положить в одну группировку

«В одной группировке **не могут быть использованы поля из не связанных друг
с другом наборов данных**. При этом наборы данных, имеющие общие родительские
наборы данных, **связанными не считаются**».

И оговорка, которая теряется первой, потому что стоит третьим предложением:
«**Исключение сделано для полей-итогов**, которые могут быть использованы
в любой группировке».

**Одноимённые поля у несвязанных наборов** (абзац после рис. 434): такие
наборы «**не могут содержать поля с одинаковыми именами**, если у них нет
общего родителя, в котором данное поле также присутствует».

## Что тянется само и что выпадает само

**Родитель приходит вместе с зависимым:** «Данные зависимого набора данных
**не могут быть получены без получения данных родительского набора**. То есть
при получении данных из зависимого набора автоматически будут получаться
и данные из родительского набора (и всех родителей родителя)».

**А незадействованный набор выпадает:** «Если ни одного поля из связанного
набора данных в настройках не задействовано, **набор данных не будет включен
в макет компоновки данных**».

**Обход идёт по последнему зависимому:** «Если в группировке используются
наборы данных из нескольких наборов данных, при исполнении компоновки будет
осуществляться обход по **последнему зависимому набору данных**».

Формулировка «наборы данных из нескольких наборов данных» — из источника,
по смыслу «поля из нескольких наборов»; орфографию не правлю.

**Стороны выражения связи** называются так, что их легко перепутать:
«В описании связи, в выражении **источника**, используются поля из набора
данных источника (**родительского** набора); в выражении связи **приемника**
используются поля набора данных приемника (**зависимого** набора данных)».

## Виды наборов данных (§10.3.1.2)

**Имя набора** (§10.3.1.2): «Имя ‑ имя набора данных, под которым к этому
набору данных можно будет обращаться из других объектов схемы компоновки
данных. В рамках одной схемы компоновки данных **имена наборов данных должны
быть уникальными**».

**Набор-запрос и пакет** (§10.3.1.2.1): «Набор данных ‑ запрос может содержать
**пакетный запрос**. Результирующим запросом будет пакетный запрос. При этом
**состав полей, которые будут помещаться во временную таблицу, автоматически
определяется по использованным в других запросах полям**». Тем же абзацем,
следующим предложением, источник договаривает: «В случае, если от временной
таблицы **не понадобилось ни одно поле**, временная таблица **не будет
помещаться в результирующий запрос**».

**Набор-объединение** (§10.3.1.2.3): «значения полей набора данных ‑
объединение будут получаться из полей вложенных наборов данных **по их пути
к данным**». То есть склейка идёт не по позиции колонки, а по пути.

**Вычисляемые поля** (§10.3.1.4) равны полям набора «**за исключением
следующего: не поддерживается использование реквизитов вычисляемых полей,
не поддерживается иерархическая группировка по вычисляемым полям**». Оговорка
несёт оба запрета — без неё пункт читается как «вычисляемые поля
равноправны».

**Ресурс считает каждую запись один раз** (§10.3.1.5): «При расчете ресурсов
**каждая запись набора данных, для которого рассчитывается ресурс, участвует
в расчете ресурса только один раз**». Это основание правила про соседние
итоги, которое стоит в теле.

## Редактирование полей: где что можно править

**Только на верхнем уровне** (§10.3.5.2): «роль поля, представление, выражение
упорядочивания, параметр, тип значения и оформление поля редактируются
**только на верхнем уровне иерархии наборов данных**».

**Заголовок поля, если его не задать** (§10.3.5.2): «система компоновки данных
пытается сформировать заголовок поля на основе синонима поля запроса. Если
синоним для поля не получен, то в качестве заголовка поля используется **путь
к данным поля, дополненный пробелами**».

Правила получения синонима источник даёт списком, и у списка два условия,
которые легко потерять. Первое — про псевдоним: «Синонимы для полей запроса
получаются **только для тех полей, у которых либо не установлен псевдоним,
либо псевдоним не отличается от псевдонима, которой был бы у данного поля
по умолчанию**». Второе — про объединения: три правила ниже действуют, только
«**Если запрос не содержит объединений**»:

«Если выражение поля запроса состоит из одного поля, то синоним получается
из этого поля. Если выражение поля является агрегатной функцией над одним
полем, то синоним поля получается из этого поля. **Для других выражений
считается, что синоним получить невозможно**».

А для запроса с объединениями правило своё: «Во всех объединениях ищется поле,
для которого можно получить синоним, использующийся в качестве синонима поля.
Если такого поля не найдено, то считается, что синоним получить невозможно».

**Диалог «Роль поля»** (§10.3.5.2): «Для поля счета в параметре Вид
**необходимо явно указать ссылку на вид счета**. Для поля измерения
в параметре Измерение **можно указать путь к данным родительского
измерения**». Второе — тот самый механизм, из-за которого реквизит измерения
тянет за собой измерение (правило в теле).

Там же: «Установленный признак **Игнорировать значения NULL** означает, что
в результат не будут включены групповые записи по данному полю, **если оно
содержит значение NULL**» — признак снимает строки, а не подставляет пустоту.
До 26.08.2026 цитата обрывалась на «если» и продолжалась словом «значение»,
взятым дальше по фразе: сшивка, которую сверка не видела, пока не научилась
проверять файлы с одними методичками.

## Ресурсы и «Рассчитывать по…»

**Умолчания** (§10.3.5.5): «По умолчанию для числовых полей устанавливается
функция **Сумма**, для нечисловых полей ‑ **Количество**». И там же:
«допускается ввод **нескольких строк для одного ресурса**».

**Привязка к группировке** (§10.3.5.5): «Если для ресурса было указано, что
его можно рассчитывать только в разрезе некоторой группировки… то данный
ресурс **будет выводиться в результат только для этой группировки
и группировок, вложенных в нее**». Ресурс исчезает из остальных группировок
молча — ошибки нет.

**Иерархия в той же колонке:** «В диалоге редактирования колонки Рассчитывать
по… для полей, по которым возможна иерархическая группировка, добавляются
строки с именем поля и **ключевым словом Иерархия**. Выражение будет
использоваться для иерархических записей группировки по полю, указанному
перед словом».

## Параметры схемы

**Обязательность собирается из двух свойств** (§10.3.5.6): «В схеме компоновки
данных для параметра Организация свойство **Использование** устанавливается
в значение **Всегда**, а свойство **Запрещать незаполненные значения** ‑
в значение **Истина**. Во время работы с отчетом пользователю недоступно
свойство Использование (он отсутствует), а незаполненное значение
отображае…». Источник разбирает только случай, когда установлены оба свойства
сразу; что будет при одном из них, он не говорит.

**Неустановленный параметр — не пустота:** «При неопределенном значении
параметра считается, что значение ‑ **нулевая ссылка на заданный тип**».
Отбор по такому параметру отработает и вернёт записи с пустой ссылкой,
а не все записи.

**`СтандартныйПериод` уже содержит время** (§10.3.5.6, пометка «Примечание»,
накрывающая абзац): «При использовании типа параметра СтандартныйПериод
следует учитывать, что даты начала и конца стандартного периода **также
содержат и время**. Причем начальная дата имеет время 00:00:00, а конечная
дата 23:59:59. Таким образом, в запросе **не обязательно использовать функции
НАЧАЛОПЕРИОДА и КО**…» — вторая половина развилки, первая половина которой
стоит в теле навыка.

## Настройки вывода: группировки и системные поля

**Вариант использования «Дополнительная информация»** (§10.3.5.9) меняет
устройство колонки и отменяет часть настроек: «Для группировок с вариантом
использования Дополнительная информация **игнорируются следующие параметры**:
Расположение полей группировки… Количество записей. Процент записей.
Расположение итогов. Расположение п…».

И одно из двух мест этого параграфа, где ошибка **всё-таки** выдаётся: «При
выполнении компоновки макета, если в группировке с вариантом использования
Дополнительная информация используется поле, которое недоступно в группировке
или в таблице, недоступно ни в одной группировке, **выдается исключение**».

Второе — там же: «Если при этом у группировки-колонки указаны поля группировки,
то при компоновке макета **будет выдана ошибка**. Для группировки-строки ‑
аналогично, только выводится одна строка, а не колонка».

**Системные поля** (§10.3.5.9.2): «система формирует специальную группу
системных полей (**СистемныеПоля, SystemFileds**)… Следует помнить, что
**системные поля не попадают в список полей, получающихся п**…».

Написание `SystemFileds` — опечатка источника, сохранена. Идентификаторы:
`СистемныеПоля.НомерПоПорядку` (`SystemFields.SerialNumber`) — «Содержит
порядковый номер строки в данном отчете. **Начинается с 1**»;
`СистемныеПоля.НомерПоПорядкуВГруппировке` (`SystemFields.GroupSerialNumber`)
— номер в текущей группировке. Обратите внимание: в имени группы источник
пишет `SystemFileds`, а в идентификаторах полей — `SystemFields`.

**Авто позиция ресурсов** (§10.3.5.9): «Не использовать ‑ в этом случае
ресурсы выводятся в том порядке, в котором перечислены поля на закладке
Выбранные поля. После всех полей ‑ в этом случае ресурсы выводятся после всех
полей».

**Поля параметров** (§10.3.5.9.3): «В выбранных полях присутствует специальная
группа Параметры, которая предоставляет возможность поместить в отчет
параметры схемы компоновки данных, **у которых установлен флажок Включать
в доступные поля**».

## Настройки по умолчанию и вариант по умолчанию

§10.3.1.12: «вариантом по умолчанию будет считаться тот вариант, **который
стоит первым в списке вариантов настроек** системы компоновки данных…
Настройки варианта по умолчанию будут применяться **при первом открытии
отчета**, при выборе команды Еще ‑ Стандартные настр…».

Перестановка вариантов местами меняет то, что увидит новый пользователь, —
и нигде больше не отражается.

## Расширение языка запросов для СКД (§10.3.3)

В наборе этот механизм встречается двумя точечными приёмами — `{ВЫБРАТЬ}`
для выбрасывания поля из вложенных запросов и `{ГДЕ}` для необязательного
параметра. Оба — частные случаи одного документированного семейства, и без
имени семейства приём выглядит трюком.

«Расширение языка запросов для системы компоновки данных осуществляется
при помощи **специальных синтаксических инструкций, заключаемых в фигурные
скобки** и помещаемых непосредственно в текст запроса».

Элементы: `ВЫБРАТЬ`, `ГДЕ`, `ХАРАКТЕРИСТИКИ`, `УПОРЯДОЧИТЬ ПО`, `ИТОГИ…ПО`,
`ПАРАМЕТРЫ`, `СГРУППИРОВАННЫЙ ПО`, `АВТОУПОРЯДОЧИВАНИЕ`, `ОБЩИЕ ИТОГИ`.

**`ВЫБРАТЬ` решает, что пользователь увидит в доступных полях:** «В этом
предложении описываются поля, которые **пользователь сможет выбирать
для вывода**. После данного ключевого слова через запятую перечисляются
псевдонимы полей из основного списка выборки запроса, которые будут доступными
для настройки».

Отсюда ответ на вопрос, который иначе выглядит загадкой: поле есть в запросе,
а в настройках его нет — потому что кто-то написал `{ВЫБРАТЬ}` и не включил
туда это поле.

**Дочерние поля — комбинацией `.*`:** «После псевдонима поля может находиться
комбинация символов «.*», что обозначает **возможность использования дочерних
полей** от данного поля».

**И ограничение на объединения:** «Элемент ВЫБРАТЬ может присутствовать
**только в первом запросе объединения**».

**`ГДЕ` — не просто отбор, а условие, которого может не быть:** «описываются
поля, на которые пользователь сможет накладывать отбор… **Если значения
параметров не заданы, то предложение ГДЕ в результирующий запрос
не включается**». На этом и построен приём `std407` против обязательных
параметров.

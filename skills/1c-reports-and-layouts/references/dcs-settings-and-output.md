# Настройки, макет компоновки и вывод результата

**Ищут по словам:** макет компоновки, макет оформления, уровень оформления,
компоновщик макета, генератор областей, расположение итогов, доступность
полей, функциональная опция в отчёте, пакетный запрос в СКД, дополнение
периодов, автоотступ, форма настроек.

Источники: руководство разработчика, глава 10, §10.4 (макет компоновки
и оформление), §10.6 (функциональные опции и права на просмотр поля),
§10.10 (использование при разработке) и §10.11 (сводка особенностей);
методические материалы 1831, 1587, 1934, 3031.

**§10.11 — самая плотная по запретам часть главы**, и вся она без нумерации:
двадцать один маркированный пункт подряд. Ссылаться на них можно только
по содержанию.

## Сводка запретов (§10.11)

**Имена, которые нельзя использовать как путь к данным:** «В системе
компоновки данных **запрещено использовать в качестве пути к данным имена,
равные ключевым словам**: ВЫБОР, КОГДА, ТОГДА, ИНАЧЕ, КОНЕЦ, ЕСТЬ, Не,
ПОДОБНО, СПЕЦСИМВОЛ, РАЗЛИЧНЫЕ».

**Пустая дата в стандартном периоде считается «не установлено»:** «Если
у параметра ‑ стандартный период дата начала или дата окончания содержит
**пустую дату**, считается, что вложенные параметры ДатаНачала
и ДатаОкончания **не установлены**».

**`РАЗЛИЧНЫЕ` и упорядочивание:** «Считается **некорректным** запрос, в котором
указано ключевое слово РАЗЛИЧНЫЕ и в предложении УПОРЯДОЧИТЬ ПО указано
выражение, **отсутствующее в списке выборки**».

**Группировка по реквизиту периода:** «Запрещена группировка
по полям-реквизитам полей-периодов» — то же, что методичка 2913 говорит
о регистраторе.

**Право на просмотр объекта убирает все поля таблицы:** «Если у пользователя
отсутствует право на интерактивный просмотр объекта метаданных, то система
компоновки считает **недоступными все поля таблицы объекта**».

**Составной тип — по одному праву:** «Дочерние поля составного типа доступны
в пользовательских настройках, **если есть право Просмотр хотя бы на одну
таблицу** из составного типа **и на само поле**».

**Функциональные опции чистят расшифровку:** «При генерации макета компоновки
данных из предопределенных макетов **удаляются выражения расшифровки**,
которые содержат поля, недоступные по функциональным опциям».

**Имя поля в иерархическом наборе:** «Поле иерархического набора данных,
с которым осуществляется связь, **должно иметь имя, как у поля в наборе
данных ‑ источнике**. В противном случае из иерархического набора данных
**не будут получаться поля-реквизиты**».

**`ПРЕДСТАВЛЕНИЕ()` при автозаполнении:** «Если в запросе набора данных
в списке выборки получается выражение, которое представляет собой применение
функции **ПРЕДСТАВЛЕНИЕ()** к выражению, получаемому в другом поле, то при
автоматическом заполнении доступных полей поле, в кот…».

**Пакетный запрос выбрасывает незадействованное:** «При использовании
в системе компоновки данных **пакетного запроса**, поля, которые
не используются в последующих запросах пакета, **удаляются из списка выборки
и полей группировки**. Если запрос, формирующий временную таблицу,
не содержит…».

Это близнец правила из §10.3.1.2.1, и они говорят об одном — не считайте
их двумя разными.

**Одно из двух мест сводки, где ошибка всё-таки выдаётся:** «При выполнении
компоновки данных **будет выдана ошибка**, если выполняется группировка
по вычисляемому полю, и в группировке указана необходимость **дополнения
в периоде**».

**Второе — про отключаемый обязательный параметр:** если у него «будет
отключено ограничение использования и параметр отключится из-за недоступности
по функциональным опциям или, непосредственно, пользователем отчета,
то при исполнении отчета **возникнет ошибка о неустановленном значении
параметра**». Оттуда же и рецепт: такому параметру «рекомендуется параметру
установить использование в значение Всегда».

**Автоотступ:** «В макетах группировки системы компоновки данных **автоотступ
выполняется только для верхней левой ячейки** макета».

## Макет компоновки: поля и наборы (§10.4.1)

**Описанное в наборе — и только оно:** «Набор данных может содержать описания
полей, которые будут доступны для этого набора данных. **Поля, описания
которых в наборе данных отсутствуют, являются недоступными**. Если некоторое
поле присутствует в запросе набора данных, но о…».

Отсюда важная оговорка к правилу тела: компоновщик добирает **описанное
в наборе данных**; чего нет в тексте запроса — добавлять неоткуда. Читатель,
знающий только §10.8.3, решит, что платформа его прикрыла.

**Вложенный набор всегда связан:** «Вложенный набор данных **всегда связан
с его родительским набором данных**. Если для вложенного набора данных указано
условие фильтра, тогда связь вложенного набора данн…».

**Источники данных:** «Допускается создание **нескольких источников данных**,
указывающих при помощи строки соединения **на одну информационную базу**».

## Макеты оформления и уровни (§10.4.3)

«Элемент оформления имеет два свойства: **Уровень** ‑ **положительное число**,
причем **если уровень равен 0**, то считается, что оформление применяется
по умолчанию ко всем макетам области определенного типа; **Оформление** ‑
коллекция, содер…».

Противоречие внутри одной фразы — «положительное число… если уровень равен 0»
— из источника. Не правим и не сглаживаем.

**Пометка «Примечание» накрывает следующий абзац:** «Если было указано
несколько уровней, то при удалении уровня группировки **всегда удаляется самый
нижний уровень текущей области, независимо от того, какой уровень в списке
был выбран**».

Удаляется не то, что выбрано. Предупреждает ли конструктор об этом, источник
не оговаривает.

**Типы макетов областей диаграммы** (§10.4.2.2): «макет диаграммы ‑ объект
типа `МакетДиаграммыОбластиКомпоновкиДанных`»; «макет ресурса диаграммы ‑
объект типа `МакетРесурсаДиаграммыОбластиКомпоновкиДанных`»; «макет
группировки диагр…».

**Как значение попадает в ячейку макета области** (§10.4.2.2): «необходимо
свойству **Значение** поля области компоновки данных (объект типа
`ПолеОбластиКомпоновкиДанных`) присвоить значение типа…».

## Генератор областей макетов (§10.4.4)

**Этапы работы** — перечень источника: «формирование общих макетов отчета»,
«формирование макетов группировок», «расположение группировок», «расположение
выводимых полей группировок», «применение м…».

**Тип макета группировки работает не везде:** «Тип макета группировки
получается из параметра `ТипМакетаГруппировкиКомпоновкиДанных` объекта
`ЗначенияПараметровВыводаКомпоновкиДанных`. Данное свойство **имеет смысл
только для простых группировок**, т. е. группировок, не входящих в таб…».

**Расположение выбранных полей, значение «Авто»:** «автоматическое определение
расположения выбранных полей: **если в группировке есть вложенная таблица,
диаграмма, вложенный отчет или группировка с типом макета группировки
Вертикальный, то выбранные поля располагаются верти**…».

То есть вложенная диаграмма меняет раскладку полей **той самой группировки,
внутрь которой её вложили**, — свойство осталось «Авто», результат другой.

**Расположение общих итогов** управляется свойствами
`РасположениеОбщихИтоговПоГоризонтали` и `РасположениеОбщихИтоговПоВертикали`;
подробности вариантов — в файле про итоги.

## Формирование макета из кода (§10.4.5)

«Формирование макета компоновки осуществляется при помощи объекта встроенного
языка **`КомпоновщикМакетаКомпоновкиДанных`**. Данный объект **не имеет
свойств** и имеет **один метод `Выполнить()`**, в который передается схема
компоновки данных, нас…».

## Формы отчёта (§10.10)

**Их генерирует платформа:** «После создания схемы компоновки данных отчет
готов к работе… Система при запуске отчета **автоматически сгенерирует форму
отчета и форму настроек**».

**Что можно задать своё** (закладка «Формы»): «кроме основной формы отчета
можно указать: **форму настроек отчета**, которая будет появляться при
выполнении команды Настройка… в режиме 1С:Предприятие и которая используется
для задания параметров пользовательски…».

**Параметры ввода** (§10.10.1): «для полей наборов данных, вычисляемых полей
и параметров имеется возможность указать **параметры ввода**. Данные параметры
описывают, **каким образом следует вводить значения** для полей в отборе
и параметрах».

## Условное оформление (§10.3.1) и цветовая политика (стандарт 676)

Это не то же, что макеты оформления выше: там оформление области, здесь —
правило «покрасить, если условие выполнено».

«**Условное оформление** Описывает, каким образом оформлять различные поля
результата. Представляет собой объект **`УсловноеОформлениеКомпоновкиДанных`**.
В свойстве Элементы этого объекта содержится коллекция элементов порядка,
состоящая из объектов `ЭлементУсловногоОформленияКомпоновкиДанных`».

**Область применения задаётся у каждого элемента:** «Для элемента условного
оформления имеется возможность **указать область применения**», и применяться
оформление может «В группировке», «В иерархической группировке», «В общ…».

**Формат и текст здесь многоязычные:** «В оформлении компоновки данных
конструктора компоновки данных параметры **Формат, Текст редактируются
как многоязычные**».

**Чем красить — задаёт `std676` п. 3** (область применения — «управляемое
приложение»), и не произвольным цветом, а элементом стиля:

- «**Негативные факты оформляются красным цветом** (элемент стиля
  "НегативноеСобытие", RGB 178,34,34) Позитивные факты оформляются зеленым
  цветом (элемент стиля "ПозитивноеСобытие", RGB 0,128,0)» (3.1);
- «Для фона ячеек с неактуальной информацией используется **розовый цвет**
  (элемент стиля "НеактуальнаяИнформация" (RGB 255,200,200)» (3.2);
- «**Итоговая информация оформляется жирным шрифтом**» (3.3);
- «Для числовых полей следует включать **выделение отрицательных значений**
  в тех случаях, когда отрицательные значения однозначно указывают на ошибку
  в анализируемых данных или являются негативным фактом» (3.4);
- «**Помеченные на удаление данные оформляются шрифтом с зачеркиванием**»
  (3.5).

**И общие итоги, которых не должно быть** (`std676` п. 4): «Если отображение
общих итогов **не имеет смысла, то его следует отключать**. Например, в отчете
"Прайс-лист" для колонки "Цена" общие итоги нужно отключить».

Отчёт без условного оформления не ошибается — он просто не показывает то,
ради чего его смотрят. Ровно тот случай «правдоподобия», которым открывается
навык.

## Функциональные опции и права на просмотр поля (§10.6)

Параграф целиком про то, как настройки отчёта **молча худеют**. Он начинается
словами «При получении настроек отчета по умолчанию система компоновки данных
автоматически выполняет следующие действия с настройками», и дальше — перечень
удалений:

- «Если у пользователя **нет права на интерактивный просмотр** некоторого поля
  или данное поле связано с **выключенными функциональными опциями**, это поле
  становится **недоступным для настройки пользователем**. То есть оно не будет
  отображаться в списке доступных полей»;
- «Если поле связано с реквизитом, **тип которого выключен функциональной
  опцией**, то это поле **удаляется** из списка доступных полей»;
- «Таблица запроса и реквизиты этой таблицы становятся недоступными, если
  функциональная опция **отключает объект конфигурации, образующий эту
  таблицу**»;
- «Если поле, на просмотр которого у пользователя нет права… используется
  в пользовательском поле, то такое **пользовательское поле удаляется**
  и по нему **не устанавливается отбор**»;
- «Из полей группировки удаляются все поля… Если после удаления поля
  группировки у группировки **не остается ни одного** поля группировки
  с установленным признаком использования, то **удаляется вся группировка**,
  а ее содержимое… помещается на место группировки»;
- «Если после удаления из таблицы группировки-строки или группировки-колонки
  таблица остается без группировок, то **таблица удаляется**»;
- «Если после удаления из диаграммы группировки-серии или группировки-точки
  диаграмма остается без группировок, то **диаграмма удаляется**».

Удалённый отбор — самое опасное здесь: пользователь видит меньше полей, но
и данных получает больше, чем задумано, потому что отбор по недоступному полю
не применился.

**Как считается недоступность составного выражения:** «Поле системы компоновки
данных считается недоступным, если **все поля, используемые в выражении этого
поля**, связаны с выключенными функциональными опциями или недоступными
на просмотр полями», причём «за исключением полей, участвующих в условиях
запросов и полей, участвующих в разделе КОГДА операции выбора».

## Исполнение: процессор компоновки (§10.5)

Генератор макета выше — предпоследний шаг. Последний — исполнение, и без него
схема с макетом остаются данными.

«Исполнение компоновки данных осуществляется при помощи объекта системы
«1С:Предприятие» **`ПроцессорКомпоновкиДанных`**. На вход процессору компоновки
данных передается макет компоновки данных».

Схема работы: `ПроцессорКД.Инициализировать(МакетКД)`, затем цикл
`ПроцессорКД.Следующий()` с выводом каждого элемента через
`ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент` —
`НачатьВывод()`, `ВывестиЭлемент()`, `ЗакончитьВывод()`.

**И три необязательных параметра инициализации, из которых первый решает
отдельную задачу:** «При инициализации процессора компоновки данных можно
дополнительно указать: объект ‑ **внешние наборы данных** ‑ структуру,
у которой в качестве ключа содержится имя внешнего набора данных, а в качестве
значения ‑ набор данных; **данные расшифровки** ‑ объект, в который будет
помещаться информация о расшифровке; **возможность использования внешних
функций** ‑ признак, можно ли в выражениях использовать функции общих модулей
конфигурации».

Внешний набор данных — штатный способ отдать компоновке уже посчитанную
в коде таблицу значений как один из наборов схемы. Не зная о нём, вывод
подмешанной части пишут руками поверх табличного документа и теряют на ней
всё, что даёт компоновка: итоги, группировки, условное оформление, макет.

Третий параметр — тот самый, о котором говорит 3332: разрешение на функции
общих модулей даётся здесь, а не в выражении.

## Чего в источнике нет

- **правил оформления как таковых.** Механизм макетов оформления описан,
  а какой брать — вопрос интерфейса, и часть его у соседа
  `1c-managed-forms`;
- **предела вложенности группировок и уровней оформления;**
- **того, как настройки переживают обновление конфигурации:** хранилища
  настроек описаны, а совместимость сохранённого варианта с изменившейся
  схемой — нет. Это стык с `1c-update-and-support`, и там ответа тоже нет;
- **вывода в макет, собранный кодом**, сверх названных способов.

# Язык выражений компоновки данных

**Ищут по словам:** язык выражений, `ВычислитьВыражение`, `ВЫЧИСЛИТЬ`, NULL,
приоритет типов, приоритеты операций, агрегатная функция, `ТАБЛИЦАЗНАЧЕНИЙ`,
`МАССИВ`, `УНИКАЛЬНЫЙИДЕНТИФИКАТОР`, общий модуль в выражении, безопасный
режим.

Источник — руководство разработчика, глава 10, §10.3.4; плюс методические
материалы 3332 «Использование функций общих модулей» и 4034.

Два правила стоят **в теле навыка**: приоритет типов при сравнении и оговорка
про И/ИЛИ у NULL. Здесь остальное.

## Две пометки во вводном абзаце, и каждая накрывает весь параграф

**«Примечание.»**: «В языке выражений компоновки данных **отсутствует
возможность получения поля через точку от выражения**». То есть
`Функция(Поле).Реквизит` написать нельзя — только от поля.

**«Внимание!»**: «**Вычисление выражения системы компоновки данных происходит
в безопасном режиме**». Что это значит и чем ограничивает — предмет навыка
«Безопасность кода».

## Литералы и пути к данным (§10.3.4.1)

«Части пути к данным отделяются друг от друга символом «.». **Имя поля
не является чувствительным к регистру**. Если путь к данным содержит
идентификатор с пробелами или специальными символами, то такие идентификаторы
**следует заключать в квадратные скобки**».

## Сравнение разнотипных значений (§10.3.4.8)

Приоритет типов стоит в теле; здесь перечень целиком, как он дан источником:
«NULL (самый низший)», «Булево», «Число», «Дата», «Строка», «ссылочные типы»,
«прочие типы».

**И отдельное правило для всего, что этим списком не покрыто:** «При сравнении
друг с другом значений, сравнение которых не описано выше, действуют следующие
правила: При выполнении **упорядочивания** используется сравнение
**по строковому представлению** сравниваемых объектов. При сравнении
в выражениях, в операциях…».

Иллюстрация набора, не источника: упорядочивание по строковому представлению
и даёт тот порядок в составном поле, который не совпадает ни с одним
из типов.

## NULL и приоритеты операций

**Правило и его исключения** (§10.3.4.9): «Любая операция, в которой значение
одного из операндов NULL, будет давать результат NULL. Есть исключения»,
и дальше перечнем: «операция И будет возвращать NULL только в случае, если
**ни один из операндов не имеет значение Ложь**»; «операция Или будет
возвращать NULL толь…».

**Приоритеты операций** (§10.3.4.10) — «первая строка имеет **низший**
приоритет», и порядок такой: «Или», «И», «Не», «В, ЕСТЬ NULL, ЕСТЬ Не NULL»,
«=, <>, <=, <, >=, >», «Бинарный +, Бинарный ‑», «*, /, %», «Унарный +,
Унарный ‑».

Обратите внимание: `ЕСТЬ NULL` приоритетнее `И`, но **менее** приоритетен, чем
сравнение, — условие вида `А = Б ЕСТЬ NULL` разбирается не так, как читается.

## Агрегатные функции с подвохом (§10.3.4.6)

**`МАССИВ` (ARRAY)**: «Функция формирует массив, содержащий значение выражения
для каждой детальной записи. В качестве параметра **можно использовать таблицу
значений**. При этом результатом работы функции будет массив, содержащий
значения **первой колонки** таблицы значений, пере…».

**`ТАБЛИЦАЗНАЧЕНИЙ` (VALUETABLE) с полями-остатками** — место, где результат
шире ожидаемого: «Если параметрами функции выступают **поля-остатки**,
то в результирующую таблицу значений попадут значения для записей
**по уникальным комбинациям измерений из других периодов**. При этом значения
получаются **только для полей-остатков, измерений, счетов, поле**…».

## `ВЫЧИСЛИТЬ` устарела (§10.3.4.11.4)

«Функция используется **для совместимости с предыдущими версиями**
«1С:Предприятия». Вместо данной функции **рекомендуется использовать функцию
ВычислитьВыражение**».

Это тот случай, где методичка спорит с руководством: приём в 4034 построен
на `Вычислить`, и приём жив, а имя функции устарело. Цитируя методичку,
называйте возраст.

## `ВычислитьВыражение` (§10.3.4.11.5)

**Три ограничения в одном абзаце**, и ни для одного источник не говорит,
выдаётся ли что-нибудь на экран:

«При указании **интервала** вычисление возможно **только для агрегатных
функций** системы компоновки данных…, для остальных функций вычисление
**не выполняется**. Функция **учитывает отбор группировок, но не учитывает
иерархические отборы**. Функция не мож…».

Вывод набора из второго ограничения: доли и проценты в иерархическом отчёте
считаются от другой базы, чем показано. Сам источник этого следствия
не формулирует.

**Перевёрнутый интервал даёт пустой результат:** «Если **конечная запись предшествует
начальной**, то считается, что записи для расчета детальных данных и расчета
агрегатных функций **отсутствуют**».

**Границы группировки:** «Если предыдущая запись **выходит за пределы
группировки** (например, для второй записи группировки требуется получить
Предыдущая(3)), то получается **первая запись группировки**». Пример источника
— про вторую запись и смещение на три; типовая задача «прирост к предыдущему
периоду» под это правило подпадает, но в источнике её нет.

**Область вычисления `ГруппировкаНеРесурса`:** «при вычислении функции для
групповой записи по ресурсам выражение будет вычислено **для первой групповой
записи исходной группировки**».

**Смещение у «Первая»:** «После слова в скобках можно указывать выражение,
результат которого будет использоваться как **смещение от начала
группировки**. Получаемое значение должно целым числом больше нуля» —
согласование «должно целым числом» из источника.

**`ОграничивающееЗначение`:** «Необходимо получить запись **по указанному
значению**. После слова ОграничивающееЗначение в скобках следует указать
выражение **первого поля упорядочивания**, со значения которого нужно начинать
фрагмент».

Наблюдение набора: привязка к **первому** полю упорядочивания хрупка — смена
сортировки выражение не меняет. Источник об этом не пишет.

**`ВычислитьВыражениеСГруппировкойМассив`, параметр отбора** (§10.3.4.11.6):
«Выражение, описывающее отбор, применяемый к детальным записям. В выражении
**не поддерживается использование агрегатных функций**».

## `УНИКАЛЬНЫЙИДЕНТИФИКАТОР` (§10.3.4.11.42)

«Параметр функции ‑ выражение, результатом вычисления которого является
**ссылочное значение** (кроме ссылки на таблицы внешних источников данных)».
Возвращаемое: «NULL ‑ NULL», «Неопределено ‑ пустой уникал…».

## Функции общих модулей в выражениях (§10.3.4.12, 3332)

**Какие модули годятся** (§10.3.4.12): «Выражение механизма компоновки данных
может содержать вызовы функций **глобальных общих модулей** конфигурации
и **неглобальных общих модулей с установленным свойством Клиент** (обычное
приложение)… или **Сервер** (при испо…)».

**Функция должна быть экспортной** (3332): «Функция **должна быть объявлена
с ключевым словом Экспорт**», а «Синтаксис обращения к функциям общих модулей
**аналогичен вызову функции из встроенного языка**».

**Два ограничения, и второе безусловно** (§10.3.4.12, последний абзац):
«использование функций общих модулей **разрешено только при указании
соответствующего параметра процессора** компоновки данных. Кроме того,
функции общих модулей **не могут быть использованы в выражениях
пользовательских полей**».

**Когда разрешение уже есть, а когда его надо давать** (3332): «Если компоновка
данных выполняется при помощи **стандартных средств объекта Отчет**,
то использование внешних функций **разрешено**. Если же компоновка данных
осуществляется **при помощи объектов системы компоновки данных**, то, для
того, чтобы разрешить использ…».

На практике это означает (вывод набора, не источника): разрешение зависит
не от выражения, а от того, кто его исполняет, — и отчёт, собранный через
стандартный объект `Отчет`, при переносе на ручную компоновку требует ещё
и явного разрешения.

## Строки внутри выражений и запроса: локализация (стандарт 762)

Область применения — «управляемое приложение, мобильное приложение, обычное
приложение». Это другой слой, чем `std766`: тот про имя макета и код языка,
этот — про строки внутри самой схемы.

**Литерал в запросе — часть интерфейса** (п. 1): «В некоторых случаях
строковые литералы из текстов запросов также могут оказаться частью
пользовательского интерфейса. В таких случаях строковые литералы
**необходимо выносить из текста запроса в параметры**».

Стандарт помечает неправильными **два** способа: и литерал прямо в тексте
запроса, и подстановку `СтрЗаменить` по имени параметра. Правильный —
параметр запроса, значение которому даёт `НСтр()` в коде.

**Вычисленная колонка обязана иметь синоним** (п. 3): «Для колонок отчета
на СКД для поля выборки, полученного вычислением с заданием ему псевдонима,
**необходимо задавать синоним при разработке. Нельзя опираться
на автоматически сгенерированный заголовок** по имени/псевдониму».

Это и есть тот случай, ради которого правило вообще существует: на языке
разработки заголовок подставится сам и будет выглядеть нормально, а в перевод
он не попадёт — «оно **не попадает в результаты поиска редактирования текстов
интерфейсов**». Расхождение всплывёт у пользователя с другим языком.

**Подстановка в заголовки** (п. 4): «Для заголовков отчетов СКД, полей,
вычисляемых полей и параметров допустимо использовать параметры подстановки
через функцию **СтрШаблон**: %1, %2 и т.д.; а также два варианта именованных
параметров подстановки: **[Параметр]**, **%Параметр%**». Заменяют их
«в обработчике модуля отчета **ПриКомпоновкеРезультата**».

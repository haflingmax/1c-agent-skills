# Параметры процедур, структуры, работа с коллекциями

Всё дословно из стандартов разработки 1С. **Область применения у всех
стандартов этого файла — «управляемое приложение, мобильное приложение,
обычное приложение».**

То, что здесь ломает работу (индексы в `НайтиСтроки`, инициализация структуры
параметров вызываемой стороной), лежит в теле раздела. Здесь — остальное:
пороги, приёмы и точные имена методов.

## Параметры процедур и функций (стандарт 640)

**Не заменять параметры другими средствами** (пункт 2): «**Не следует**
использовать вместо параметров функций другие средства конфигурирования
(переменные модулей, реквизиты формы и т.п.)».

**Порядок — от общего к частному** (пункт 3):

```bsl
// Неправильно:
Процедура ПоменятьЦветПоляФормы(Цвет, ИмяПоля, Форма)
// Правильно — основной параметр первым:
Процедура ПоменятьЦветПоляФормы(Форма, ИмяПоля, Цвет)
```

**Необязательные — после обязательных** (пункт 4): «Необязательные параметры
(параметры со значениями по умолчанию) **должны** располагаться после
обязательных параметров».

**Два порога** (пункт 5): «**Не рекомендуется** объявлять в функциях много
параметров (нужно ориентироваться на количество **не более семи** параметров),
при этом не должно быть много параметров со значениями по умолчанию (нужно
ориентироваться на количество **не более трёх** таких параметров)».

Причина названа предметно: «можно легко ошибиться в количестве запятых
при передаче необязательных параметров».

Два выхода, оба из источника: «группировать однотипные параметры в один или
несколько составных параметров типа `Структура`… либо полностью пересмотреть
логику работы функции, например, разделив ее на несколько разных, более
простых функций».

**Вложенные вызовы в параметрах** (6.1): «**Не рекомендуется** при передаче
параметров в одну функцию применять вложенные вызовы других функций…
Правильно разбивать такие вызовы на отдельные операторы с помощью
вспомогательных локальных переменных».

Оговорка там же, и она существенна: «если код с вложенными вызовами получается
компактным (не требует переноса выражений) и легко читаемым, то вложенные
вызовы **допустимы**». Пример допустимого из источника:
`ПеречитатьСуммуПоКурсу(Сумма, КурсВалютыНаДату(Валюта));`

**Вложенный конструктор структуры** (6.2): «**не рекомендуется** при вызове
функций использовать вложенный конструктор структуры: `Новый Структура(...)`.
Вложенное объявление структуры допустимо только в тех случаях, когда количество
ее свойств небольшое (нужно ориентироваться на количество свойств **не более
трёх**)».

**Обязательные параметры не пропускают** (пункт 7): «При вызове функций
**не следует** пропускать обязательные параметры. В противном случае, в параметр
будет передано значение `Неопределено`, на которое функция может быть
не рассчитана. Если же значение `Неопределено` является допустимым, то нужно
или его передавать в функцию явно, или сделать этот параметр необязательным
со значением по умолчанию `Неопределено`».

```bsl
// Неправильно:
ПоменятьЦветПоляФормы(,"РезультатПроверки", ЦветаСтиля.ПоясняющийОшибкуТекст);
// Правильно:
ПоменятьЦветПоляФормы(ЭтотОбъект, "РезультатПроверки", Цвет);
```

## Структуры (стандарт 693)

**Порог конструктора** (пункт 1): «При создании объекта типа `Структура`
**не рекомендуется** передавать в конструктор более **3-х** значений свойств.
Вместо этого рекомендуется использовать метод `Вставить` или присваивать
значения свойствам явным образом».

**Конструктор в конструкторе** (пункт 2): «**Не рекомендуется** в конструкторе
структуры использовать конструкторы других объектов, **если эти конструкторы
принимают параметры**. В частности в конструкторе одной структуры
не рекомендуется создавать другие структуры с объявлением значений свойств».

Условие «если принимают параметры» — часть правила: `Новый Структура` без
аргументов под запрет не подпадает.

**Функции в конструкторе** (пункт 3): «**Не рекомендуется** в конструкторе
структуры вызывать функции с большим (**более 3**) количеством параметров».

**Состав структуры задают сразу** (4.1): «**Не рекомендуется** в разных частях
программного кода добавлять в структуру свойства и затем проверять их наличие
в структуре. Следует сразу создавать структуру со значением свойств
по умолчанию».

Довод не только про читаемость: «это позволяет эффективнее применять различные
средства автоматической проверки и обработки кода».

```bsl
// Неправильно:
ПараметрыВыполнения = Новый Структура;
// …
УникальныйИдентификатор = ?(ПараметрыВыполнения.Свойство("УникальныйИдентификатор"),
	ПараметрыВыполнения.УникальныйИдентификатор, Неопределено);

// Правильно — конструктор со значениями по умолчанию:
Функция ПараметрыВыполнения()
	Результат = Новый Структура;
	Результат.Вставить("УникальныйИдентификатор", Неопределено);
	Возврат Результат;
КонецФункции
```

**Исключения** (4.2) — «структуры, формат которых не фиксирован»: «полученные
из внешних источников: результат HTTP-запроса, данные со сканера штрихкодов,
терминала сбора данных и т.п.» и «системные параметры формы, параметры выбора
в параметрах формы».

Примечание оттуда же: «пользовательские параметры формы **необходимо объявлять
явно** на закладке Параметры редактора формы».

## Копирование строк между таблицами (стандарт 448)

«При копировании строк между различными таблицами значений (табличными частями
и т.п.) со схожим составом колонок **следует использовать метод глобального
контекста `ЗаполнитьЗначенияСвойств`**. Алгоритмы, использующие данный метод
значительно эффективнее, чем например, многократный перебор колонок таблицы
значений, выполняемый для получения их состава».

```bsl
Для Каждого СтрокаТаблицыИсточника Из ТаблицаИсточник Цикл
	СтрокаТаблицыПриемника = ТаблицаПриемник.Добавить();
	ЗаполнитьЗначенияСвойств(СтрокаТаблицыПриемника, СтрокаТаблицыИсточника);
КонецЦикла;
```

## Определение типа (стандарт 442)

«Определение типа значения переменной **необходимо** выполнять путём его
сравнения с типом, а не каким-либо другим методом».

```bsl
// Правильно:
Если ТипЗнч(Ссылка) = Тип("ДокументСсылка.ПоступлениеТоваровУслуг") Тогда
// Неправильно:
Если Ссылка.Метаданные().Имя = "ПоступлениеТоваровУслуг" Тогда
```

## Массовая конкатенация строк (стандарт 782)

«При массовых операциях конкатенации строк **следует использовать методы
платформы `СтрРазделить` и `СтрСоединить`». Выигрыш назван двойной: «не только
быстрее выполняется, но и приводит к снижению потребления оперативной памяти».

**Что считать массовым** — примечание стандарта, без которого правило
применяется не туда: «следует ориентироваться на **1000 операций конкатенации
строк и более** (эта величина также может быть еще меньше при увеличении длин
строк: чем строки длиннее, тем операции выполняются дольше). Особого внимания
требует конкатенация **в циклах и в универсальных механизмах**, которые могут
применяться на сколь угодно больших объемах данных».

И встречная оговорка, которая теряется первой: «В то же время, **не следует
отказываться от конкатенации строк в остальных случаях**, так как это заметно
снижает читаемость кода».

```bsl
// Неправильно (в цикле):
ИзвлеченныйТекст = ИзвлеченныйТекст + Символы.ПС + ТекстОбласти;

// Правильно:
ИзвлеченныеТексты = Новый Массив;
// … ИзвлеченныеТексты.Добавить(ТекстОбласти);
ИзвлеченныйТекст = СтрСоединить(ИзвлеченныеТексты, Символы.ПС);
```

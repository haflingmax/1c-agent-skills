# Исключения и журнал регистрации: подробности

Головные правила — в теле раздела: не перехватывать без нужды, не оставлять
пустой `Исключение`, не разбирать текст исключения. Здесь то, что нужно, когда
перехват уже уместен, и всё про журнал регистрации.

**Область применения** у двух стандартов разная и обе уже́ обычной:
стандарт 499 — «управляемое приложение, мобильное приложение, обычное
приложение», но у его **раздела 3** стоит отдельная строка «Область применения
(уточнение): управляемое приложение, обычное приложение»; стандарт 498 —
«управляемое приложение, обычное приложение», без мобильного.

## Когда перехват уместен (стандарт 499, раздел 2)

Случай назван предметно: «В ряде случаев технологический текст исключения
непонятен, поэтому его нужно дополнить прикладной, понятной пользователю
информацией, типовыми причинами или рекомендациями по устранению возникшей
проблемы. К этой категории проблем относятся, как правило, недоступность
внешних ресурсов и каналов связи, некорректная работа внешних сервисов,
некорректные входные данные и некорректные настройки используемых внешних
приложений. Например, это проблемы взаимодействия с почтовыми серверами,
веб-сервисами, принтерами, криптопровайдерами».

**Проброс с уточнением** (2.1): «допустимо перехватить и пробросить исключение
**без потери исходного содержания** с необходимым уточнением».

**Блок должен быть узким** (2.1): «**не следует открывать большие блоки
Попытки-Исключение**, а расставлять их локально на конкретные потенциально
проблемные места, вызовы конкретных методов платформы, чтобы исключить
перехват других несвязанных ошибок, например, ошибок соседнего программного
кода».

**Как проверять вывод** (2.1): «рекомендуется запускать 1С:Предприятие
**без отладки и без режима технического специалиста**, т.к. в зависимости
от этого в платформе 1С:Предприятие внешний вид и поведение окна исключения
различается».

## Когда исключение обрабатывается, а не перевызывается (пункт 2.2)

Случай назван — «как например в обработчиках обновления информационной базы».
Тогда **следует**:

- «фильтровать и отправлять ошибки программного кода в сервис регистрации
  ошибок — см. `ИнформацияОбОшибке.ЯвляетсяОшибкойКатегории`
  и `ОтчетОбОшибке.Отправить`»;
- «фиксировать причину ошибки в журнале регистрации для того, чтобы системный
  администратор имел возможность выполнить диагностику проблемы»;
- «записывать в журнал регистрации подробное представление исключения,
  а сообщение об ошибке для пользователя добавлять в текст сообщения — см.
  `ОбработкаОшибок.ПодробноеПредставлениеОшибки`
  и `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя`».

И **не следует** — две подмены, каждая с названной причиной:

| Взяли | Надо | Почему |
|---|---|---|
| `ОписаниеОшибки` | `ОбработкаОшибок.ПодробноеПредставлениеОшибки` | «неинформативна для разработчика, потому что **не возвращает стек** в тексте ошибки» |
| `ОбработкаОшибок.КраткоеПредставлениеОшибки` | `ОбработкаОшибок.СообщениеОбОшибкеДляПользователя` | «не возвращает уточнений, добавленных при пробросе исключения» |

## Журнал регистрации (стандарт 498)

**Когда писать из встроенного языка** (пункт 2): «**Рекомендуется** производить
запись в журнал регистрации из встроенного языка в тех случаях, когда
администратору необходимо сообщить дополнительную диагностическую информацию
о событиях, **которые не записываются платформой**». И правило гранулярности:
«одна его запись должна соответствовать одному событию».

### Тип события (2.1)

**Группировать по функциональному признаку**, точка — разделитель:
«"Название группы событий.Название события"».

```
// Правильно:
Поручения.Уведомление о новых задачах
Поручения.Уведомление о зависших задачах
// Неправильно — «плоские» типы:
Уведомление о новых задачах
```

**Данных в типе события быть не должно:** «Тип события предназначен для отбора
однотипных записей из журнала регистрации, поэтому неправильно включать в него
любую избыточную информацию — конкретные значения из информационной базы или
внешних систем».

```
// Неправильно:
Не удалось отменить проведение документа <Реализация КП00-00002 от 11>
// Правильно — общий тип, а данные в параметрах:
Проведение документов.Не удалось отменить проведение
```

Метаданные кладут в параметр **`Метаданные`**, данные — в параметр **`Данные`**
метода `ЗаписьЖурналаРегистрации`.

«Текст типа события — локализуем, при этом **всегда задаётся основной язык
конфигурации**».

### Уровень важности (2.2)

| Уровень | Что записывают |
|---|---|
| «Ошибка» | «Критичные события, требующие повышенного внимания администратора (ошибки бизнес-логики, сбои в программе, и т.п.)» |
| «Предупреждение» | «Потенциальные проблемы и не фатальные ошибки» |
| «Информация» | «Для вывода информационных сообщений об успешном завершении той или иной операции» |
| «Примечание» | «более низкий уровень важности» |

### Комментарий (2.3)

- «Не следует помещать в комментарий информацию **сразу о нескольких
  событиях**» — «правильно записать столько событий, сколько их реально
  произошло»;
- «Не следует помещать в комментарии текстовые данные, размер которых заранее
  не известен и может быть сколько угодно большим. Например, содержимое файлов,
  ответов веб-сервисов и т.п. **Следует ориентироваться на максимум 10 Кб**»;
- «Текст комментария — локализуем»;
- для исключения — «следует использовать конструкцию:
  `ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке())`».

Образец стандарта — три записи на одно действие, две информационные
и одна на ошибку:

```bsl
Попытка
	ЗаписьЖурналаРегистрации(НСтр("ru = 'Мой механизм.Действие с возможной ошибкой'", КодОсновногоЯзыка),
		УровеньЖурналаРегистрации.Информация, , , НСтр("ru = 'Начато действие'"));
	ДействиеСВозможнойОшибкой(ОбъектДействия);
	ЗаписьЖурналаРегистрации(НСтр("ru = 'Мой механизм.Действие с возможной ошибкой'", КодОсновногоЯзыка),
		УровеньЖурналаРегистрации.Информация, , , НСтр("ru = 'Завершено действие'"));
Исключение
	ЗаписьЖурналаРегистрации(НСтр("ru = 'Мой механизм.Действие с возможной ошибкой'", КодОсновногоЯзыка),
		УровеньЖурналаРегистрации.Ошибка, , ,
		НСтр("ru = 'Во время выполнения действия произошла неизвестная ошибка.'")
			+ Символы.ПС + ОбработкаОшибок.ПодробноеПредставлениеОшибки(ИнформацияОбОшибке()));
КонецПопытки;
```

`КодОсновногоЯзыка` здесь — «код языка для хранения данных в информационной
базе».

### Журнал — не источник для быстрых выборок (пункт 3)

«**Не следует** использовать выборку из журнала регистрации в тех задачах, где
критична высокая скорость выполнения выборки. Поскольку при больших объёмах
журнала регистрации **скорость выборки падает пропорционально увеличению его
объёма**».

Что вместо: «Рекомендуется заводить **отдельный регистр** для протоколирования
интересующих событий или обращаться к специализированным объектам платформы
(например, `МенеджерФоновыхЗаданий` для выборки истории выполнения фоновых
заданий)». И там же: «Эту особенность нужно также учитывать при разработке
отчётов по журналу регистрации».

## Чего в стандартах 498 и 499 нет

- **признака, по которому отличают «ошибку, которую надо записать» от той,
  которую не надо.** Стандарт называет случаи, когда запись уместна, и меры
  «сколько записей — много» не даёт;
- **разбора журнала:** как достать из него факт и почему добытое бывает
  неполным — у соседа `1c-quality-gates` (`event-log-as-evidence.md`);
- **хозяйства журнала** — уровни, периоды, сокращение, форматы: у соседа
  `1c-publish-and-operate` (`event-log-admin.md`);
- **того, что делать с уже пойманным исключением на бою:** стандарты
  описывают, как писать код, а не как разбирать происшествие.

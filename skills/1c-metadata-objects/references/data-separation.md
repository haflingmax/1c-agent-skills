# Разделение данных: где область данных открывается или смешивается молча

**Ищут по словам:** разделитель, общий реквизит-разделитель, область данных,
«Независимо», «Независимо и совместно», параметр сеанса разделителя,
условное разделение, `/Z`, `Zn`, `<zones>` в default.vrd, разделение
пользователей, разделение аутентификации, `УстановитьБезопасныйРежимРазделенияДанных`,
несколько разделителей, модель сервиса, абонент.

Источник: руководство разработчика 8.3.27, глава 24 «Механизм разделения
данных». Правила про общие реквизиты-разделители, включая их порядок
в дереве метаданных, — стандарт 677 (разбор в `attributes-and-types.md`). Удаление
области данных — `/EraseData` у соседа `1c-publish-and-operate`
(`ib-admin.md`); разделение расширений — у соседа `1c-extensions`
(`rib-and-profiles.md`).

**Спина главы: платформа сама фильтрует чтение и сама проверяет запись —
но только по тем параметрам сеанса, которые ей дали.** Где параметр
выставлен неверно, отбор идёт по чужой области, и ошибкой это становится
не всегда.

## Чтение фильтруется, запись проверяется, и не одинаково

«Во всех операциях чтения записей базы данных «1С:Предприятие»
автоматически отбирает только те записи, в которых значения используемых
разделителей совпадают с текущими значениями разделителей» (§24.1).

Запись строже: «платформа проверяет, что записываемые данные содержат
значения используемых разделителей, равные текущим значениям разделителей
или равные значениям по умолчанию для соответствующих типов. Если это
не так, то вызывается исключение». Пример источника — объект, прочитанный
в области 1, после смены параметра сеанса на 2 не запишется.

**А для неиспользуемого разделителя обе защиты снимаются:** «при чтении
данных отбор по этим разделителям не выполняется; при модификации данных
используются значения, содержащиеся в записываемых данных».

**Вывод набора, а не источника:** сеанс, где разделитель выключен, видит
все области разом и пишет в ту, чьё значение лежит в объекте. Регламентное
задание или обработка, запущенные без разделителя, работают по всей базе,
и ни чтение, ни запись об этом не сообщают.

## Два режима, и в одном ссылки совпадают между областями

Свойство «Использование разделяемых данных» (§24.2.1):

- **«Независимо»** — без разделителя в сеансе обращение к разделённым
  объектам запрещено; сам разделитель «недоступен в объектной модели,
  в языке запросов, в формате выгрузки в XML и XDTO, а также ограничениях
  доступа к данным». И предупреждение: «В этом режиме ссылки объектов базы
  данных **могут быть одинаковыми** для объектов, записанных в разных
  областях данных»;
- **«Независимо и совместно»** — работать можно и без разделителя,
  разделитель виден в запросах и ограничениях доступа, ссылки между
  областями «не могут быть одинаковыми». Цена: «невозможно создание
  предопределенных элементов» и «не поддерживается любое расширение
  данных».

**Вывод набора:** в режиме «Независимо» ссылку нельзя считать глобальным
идентификатором — две области могут держать разные объекты с одинаковой
ссылкой, и выгрузка из одной области в другую по ссылкам их склеит.

Ограничения самого разделителя: «Тип разделителя не может быть составным»;
при типе Строка на MS SQL Server «не допускается изменение языка
региональных настроек информационной базы»; и разделение «Не поддерживается»
на MS SQL Server 2000, IBM Db2 9.1 и на Db2 с регистрозависимым сравнением
строк (§24.1).

## Смена параметра сеанса разделителя — без гарантии целостности

Значение и признак использования разделителя хранятся в параметрах сеанса
(§24.2.2), и тип параметра «в точности должен совпадать с типом
разделителя». Менять их из кода можно при наличии прав, но источник
предупреждает прямо: «**«1С:Предприятие» не гарантирует целостность
данных приложения после изменения параметров сеанса**».

Что происходит при смене: «очищается кеш объектов; удаляются повторно
используемые значения … и на стороне клиента, и на стороне сервера».

## `/Z` читает разделители по порядку в дереве — и сортировка его ломает

Значения разделителей при запуске задаются параметром `/Z`, в строке
соединения и внешнем соединении — `Zn`, в веб-клиенте — тем же `Z`
в адресе (§24.4). Формат — пары «признак, значение» через запятую,
и соответствие позиционное (§24.4.2):

> «Пропуск разделителей невозможен. Порядок следования пар
> <Признак><Значение> соответствует порядку расположения разделителей
> в окне конфигурации. Если порядок общих реквизитов меняется (например,
> выполнена сортировка списка общих реквизитов), необходимо изменить
> расположение значений в параметре Z.»

**Это самое опасное место главы.** Сортировка общих реквизитов
в конфигураторе — действие, которое не выглядит изменением данных, —
переставляет смысл всех строк запуска, ярлыков и строк соединения:
значение абонента уходит в разделитель организации. Стандарт 677 п. 3
требует подбирать порядок разделителей под порядок установки параметров
сеанса (`attributes-and-types.md`); глава 24 добавляет, что от этого
порядка зависят и строки `/Z`.

Остальные правила значения:

- для ссылочного типа указывается код или номер, и «Коды и номера должны
  быть уникальны среди всех значений соответствующего объекта
  конфигурации»; при неоднозначности «будет вызвано исключение»;
- «Не допускается использование справочников с длиной кода, равной 0,
  и документов с нумераторами»;
- дата — ровно 14 цифр; «+» или «-» в начале значения и «,» внутри него
  удваиваются;
- признак «-» выключает разделитель, но значение, если указано, всё равно
  записывается в параметр сеанса.

**Расхождение со значением у пользователя** (§24.4.1): если оно есть,
значение из строки запуска берётся, только если у пользователя есть право
менять параметры сеанса разделителя, — «Иначе аутентификация пользователя
выполнена не будет».

## Пользователи и аутентификация по областям

«Разделение пользователей» (§24.2.3) решает, кого видно. Таблица источника
для одного разделителя: у пользователя значение задано — он доступен при
равенстве значений, если разделитель используется, и доступен всегда, если
нет; значение не задано — **недоступен** при используемом разделителе
и доступен при неиспользуемом.

«Разделение аутентификации» (§24.2.4) разрешает одноимённых пользователей
в разных областях — например, несколько «Администратор», «которые будут
различаться только значениями разделителей (в том числе и для незаданного
значения разделителя)». При «Не использовать» имена уникальны по всей базе.

## Условное разделение: первый запуск выключает разделение

Условное разделение (§24.2.6) включает и выключает разделитель константой
или реквизитом другого разделителя. Главное предупреждение стоит
у варианта с константой (§24.2.6.2.1):

> «При первом запуске «1С:Предприятия» (после добавления условного
> разделения) значение константы будет равно Ложь, и разделение будет
> выключено.»

А выключенное разделение значит (§24.2.6.1): текущие значения параметров
сеанса «игнорируются», и используется «Значение разделителя ‑ значение
по умолчанию для типа разделителя». В примере источника при `Ложь`
видны только записи с абонентом 0.

**Вывод набора, а не источника:** добавить условное разделение в работающую
разделённую базу значит в момент первого запуска перевести всех абонентов
в общую область значения по умолчанию — их данные «пропадут» из списков,
а новые записи лягут в общую область. Константу включают до того, как
пускают пользователей.

Прочие правила условного разделения:

- «Условное разделение не работает в конфигураторе. Считается, что в сеансе
  конфигуратора реквизиты всегда условно включены»;
- «Если значение, определяющее условное разделение, не прочитано или
  неоднозначно, будет выдано исключение»;
- зависимость одного разделителя от другого цепная: «Если разделитель,
  который используется в условном разделении другого разделителя,
  не используется, то другой разделитель также считается неиспользуемым».

**В распределённой базе условное разделение включается, но не выключается**
(§24.2.6.4): при автоматической регистрации изменений управляющий объект
в разделённом сеансе можно менять, только «когда текущее состояние объекта
равно Ложь. То есть можно только включить условное разделение, и нельзя
его выключить». А смена в главном узле действует на всю систему:
«В периферийных базах пользователи могут «потерять» все свои данные».
Отсюда требование источника — менять управляющий реквизит может только
администратор области или всей базы.

## Несколько разделителей складываются «по И»

Доступность действия считается по каждому разделителю отдельно, и «Результат
по всем разделителям складывается «по И»» (§24.3). Пример источника: при
двух независимых разделителях и одном неиспользуемом список справочника,
разделённого обоими, недоступен — «Истина И Ложь = Ложь».

## Безопасный режим разделения: считать включения

`УстановитьБезопасныйРежимРазделенияДанных()` (§24.5) запрещает коду менять
значение и использование разделителя и объекты условного разделения — это
защита от кода, «надежность» которого «в общем случае, проверить
не представляется возможным», при переходах по областям в регламентных
операциях.

- Включённый через `default.vrd` (`safe="true"` у `zone`) режим методом
  не выключить: «отключить его с помощью метода
  УстановитьБезопасныйРежимРазделенияДанных() невозможно»;
- включения и выключения должны сходиться; незакрытые включения платформа
  сама снимает при выходе из процедуры, а лишнее выключение — «будет
  вызвано исключение».

Для веб-доступа из интернета источник называет настройку `<zones>`
в `default.vrd` как способ получить гарантию, что «будет невозможно
получить доступ к другой области данных» (§24.4.3.2).

## Удаление области данных: что ещё уходит

Сама команда и главная ловушка — `/EraseData` без разделителя стирает всю
базу — у соседа `1c-publish-and-operate`. Из перечня §24.6 сверх этого:
удаляются хранилища настроек, история работы пользователя, список
пользователей, данные регистрации в сервисе взаимодействия; «Если в сеансе
не используется ни один разделитель, то будут удалены все сохраненные
политики паролей»; поведение истории данных зависит от набора разделителей
в сеансе. Совет источника после вызова метода: «Сразу после выполнения
метода рекомендуется сменить значения разделителей, определяющих область
данных».

## Чего в главе 24 нет

- **модели сервиса как готового решения.** Глава описывает механизм
  платформы, а как организовать абонентов, регламентные операции по
  областям и обновление, не говорит — это БСП и её технология сервиса,
  вне охвата набора;
- **признака, по которому код узнаёт, что работает без разделителя
  по всей базе,** — кроме чтения параметров сеанса самим кодом;
- **чисел:** сколько областей выдерживает база и как растут таблицы,
  глава не говорит;
- **поведения объектов системы при разделении** — §24.7 отсылает за ним
  в другое место руководства.

# Стандартный интерфейс OData

**Ищут по словам:** OData, `standard.odata`, `$filter`, `$top`, `$skip`,
`$select`, `$expand`, `allowedOnly`, префикс имени ресурса, `RowType`,
`RecordType`, `like`, `substringof`, `dateadd`, коды ошибок OData,
публикация OData.

Источник: руководство разработчика, глава 17, §17.4.

Правило про закрытый список типов объектов стоит **в теле навыка**; здесь
остальное.

## Имя ресурса собирается по правилу (§17.4.4)

«При обращении к какому-либо ресурсу, его идентификатор формируется
по следующему принципу: **ПрефиксИмени_ИмяОбъектаКонфигурации_СуффиксИмени**».

Имя берётся ровно из конфигуратора: «ИмяОбъектаКонфигурации ‑ свойство Имя
объекта конфигурации, как оно задано при разработке прикладного решения
в конфигураторе».

Отсюда прямое следствие для интеграции: **переименование объекта метаданных
меняет публичный адрес ресурса**. Потребитель OData ходит по имени, которое
для вас внутреннее.

**Префиксов четырнадцать**, и список закрыт: `Catalog`, `Document`,
`DocumentJournal`, `Constant`, `ExchangePlan`, `ChartOfAccounts`,
`ChartOfCalculationTypes`, `ChartOfCharacteristicTypes`,
`InformationRegister`, `AccumulationRegister`, `CalculationRegister`,
`AccountingRegister`, `BusinessProcess`, `Task`.

В нём нет перечислений, отчётов, обработок, общих модулей и ролей. Прямого
«эти типы недоступны» источник не пишет — это следует только из закрытости
таблицы, и это разница между «не нашёл» и «нельзя».

**Суффиксы** — тоже закрытый список: имя табличной части, имя реквизита
табличной части или набора записей, имя виртуальной таблицы регистра,
`RowType`, `RecordType`.

Виртуальная таблица приходит функцией: «Имя функции совпадает с английским
вариантом имени используемой виртуальной таблицы языка запросов».

## Заголовок §17.4.5 шире своего содержания

«Правила формирования условия отбора» накрывают четыре разнородных
параметра, и три из них к условию отбора отношения не имеют: `$top` —
ограничение количества, `allowedOnly` — переключатель прав, `$skip` —
постраничный пропуск. Условие отбора — только `$filter`.

## `$filter`: язык свой, но одна функция чужая

Операции закрытыми списками: логические `eq`, `ne`, `gt`, `ge`, `lt`, `le`,
`or`, `and`, `not`; арифметические `add`, `sub`, `mul`, `div`; скобки для
приоритета. «Операции с одинаковым приоритетом вычисляются слева направо».

**Ловушка в строковых функциях одна, и она про совместимость:**
`like(Str, Template)` — «Возвращает true, если значение Str1 удовлетворяет
шаблону Template. **Синтаксис шаблона аналогичен функции ПОДОБНО() языка
запросов**».

То есть шаблон здесь — не стандартный для OData, а 1С-овский. Потребитель,
пишущий по спецификации протокола, получит не то, что ожидал, и ошибки
при этом не будет.

**Даты работают с закрытым набором единиц:** «second ‑ секунды; minute ‑
минуты; hour ‑ часы; day ‑ дни; month ‑ месяцы; quarter ‑ кварталы; year ‑
года». Ни недели, ни декады в нём нет.

## `allowedOnly`: ошибка не гарантирована ни в ту, ни в другую сторону

«Если при выполнении запроса необходимо получить только те объекты данных,
которые не попадают под ограничения доступа к данным, то в URL получения
данных **необходимо добавить параметр allowedOnly**».

А без него: «Если параметр не указан или указан со значением false,
то во время исполнения запроса к данным **может возникнуть ошибка с кодом
401**… **Ошибка может не произойти** в том случае, если были указаны
дополнительные условия, которые ограничили выборку только разрешенными
данными».

Двойное «может» — не расплывчатость источника, а описание механики: 401
зависит от того, попали ли запрещённые данные именно в эту выборку.
Один и тот же запрос на разных данных ведёт себя по-разному, и тест
на «своих» данных этого не покажет.

## Расхождение заголовка ещё в одном месте

**§17.4.9 «Выполнение функций и действий»** описывает только функции;
пример действия (проведение и отмена проведения документа) лежит
в §17.4.13.1.7 под совсем другим заголовком. Искать «действия» по номеру
параграфа бесполезно.

## Чего в §17.4 нет

- **под чьей учётной записью выполняется OData-запрос** — глава не говорит
  вовсе. Про права есть только результат их проверки: код ошибки 20
  в таблице кодов и параметр `allowedOnly`. Схем аутентификации — Basic,
  NTLM — для OData не названо ни одной, в отличие от web-сервисов;
- **явного «остальные типы недоступны»** — только закрытая таблица
  префиксов;
- **массовая выгрузка и её цена**: §17.4.1 называет загрузку и выгрузку
  данных типовой задачей OData, а вся детализация главы — про одиночные
  сущности и наборы через `$filter`, `$top`, `$skip`.

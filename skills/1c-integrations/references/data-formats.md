# Форматы данных: где обмен молча теряет тип

**Ищут по словам:** XDTO, фабрика XDTO, схема XSD, пакет XDTO, JSON,
`ЗаписатьJSON`, `ПрочитатьJSON`, функция восстановления JSON,
`#type`, двоичные данные, буфер двоичных данных, `ЧтениеДанных`,
`ЗаписьДанных`, поток, PDF, `ДокументPDF`, электронная подпись PDF,
регулярное выражение, именованные группы, распознавание речи, архив ZIP.

Источник: руководство разработчика 8.3.27, глава 16 «Работа с различными
форматами данных». Глава большая (246 тыс. знаков) и по большей части
описывает API — это работа синтакс-помощника. Здесь взято другое:
**места, где формат работает не так, как ожидает пишущий код,
и не сообщает об этом.**

Правила обмена — у соседних файлов этого раздела (`exchange-standards.md`,
`odata.md`, `web-services.md`); здесь устройство самих форматов.

## JSON: не всякий документ ложится в структуру

«ключ элемента структуры подчиняется правилам формирования переменной
на встроенном языке, а ключ элемента соответствия может быть любым.
С учетом того, что JSON не накладывает ограничений на значение ключа,
**не все JSON-документы можно прочитать в структуру**» (§16.2.1).

Разница не только в чтении: «к элементам структуры можно обращаться
«через точку», а к элементам соответствия такой доступ не
предоставляется».

**Отсюда практический выбор:** структура удобнее, соответствие надёжнее.
Чужой JSON, чьи ключи вы не контролируете, читают в соответствие —
иначе документ с ключом `«total-sum»` или `«2024»` не прочитается вовсе.

## Функция восстановления меняет значение, но не тип

При чтении JSON можно передать функцию восстановления. Её граница названа
прямо: «в этой функции можно заменить значение, которое считано
из JSON-документа, **но нельзя изменить тип считываемого объекта**»
(§16.2.3.3.3).

Два случая, когда её вообще не позовут: «Для значений Неопределено
функция восстановления не вызывается» и «Функция восстановления также
не будет вызываться для служебных свойств, которые создаются
и используются системой «1С:Предприятие», например, #type, #ns и т. д.».

**И асимметрия техник:** «не поддерживается использование функции
преобразования при операции сериализации, в отличие от потоковой».
То, что можно на потоковой записи, нельзя на объектной.

## Без явного типа JSON не читается обратно

Про сериализацию значений 1С сказано на примере: «Предыдущий пример
сериализации элемента справочника Валюты будет **невозможно
десериализовать без явного указания типа значения**».

И жёстче — про чтение через XDTO: «Выполнить чтение JSON-документа
в том случае, если в нем используются типы, которые неизвестны фабрике
XDTO, с помощью которой выполняется чтение документа ‑ **невозможно**».

**Вывод набора, а не источника:** JSON, записанный «как есть» без
служебного `#type`, годится наружу и не годится обратно в 1С. Обмен
1С↔1С и обмен 1С↔чужая система требуют разных настроек записи, и это
решение принимают до первой выгрузки, а не после.

## XDTO: фабрику собирают целиком

«Сценарий, при котором типы XDTO **добавляются в фабрику по одному или
группами, не поддерживается**» (§16.1.2). Фабрику получают из схемы
или набора схем целиком.

И запрет на пересечение: «Пакеты, входящие в модель, должны иметь
уникальные URI пространства имен ‑ **дублирование пакетов в рамках
модели запрещено**».

Про значения по умолчанию есть тонкость, из-за которой проверка
«заполнено ли» врёт: «При создании объекта XDTO свойство, если оно
допускает единственное значение, принимает значение по умолчанию (метод
Установлено() объекта XDTO возвращает значение **Ложь** для этого
свойства)». То есть значение есть, а `Установлено()` говорит «нет».

Для множественных свойств иначе: «Для свойств с множеством значений
список значений изначально пуст, независимо от того, определено или нет
значение по умолчанию».

## Двоичные данные: два объекта на один поток не садятся

«**Не рекомендуется одновременное использование объектов
ЧтениеДанных/ЗаписьДанных и потоковых объектов**», и жёстче: «Также **не
поддерживается** одновременное использование объектов ЧтениеДанных
и ЗаписьДанных, которые используют для своей работы один поток»
(§16.3.6).

Буфер двоичных данных читает не всё: «Чтение строки, однако,
не поддерживается буфером двоичных данных» — строку получают отдельно,
`ПолучитьСтрокуИзБуфераДвоичныхДанных()`.

**И оговорка про битовые операции, которую легко пропустить:** «так-как
система типов «1С:Предприятия» не предполагает наличие
специализированных без знаковых типов ограниченной разрядности, все
дальнейшие методы опираются на предположение о том, что передаются целые,
без знаковые числа» (орфография источника). Знаковое число в
`ПроверитьБит()` даст ответ, а не ошибку.

## PDF: подписанный документ изменить нельзя

Два запрета названы прямо (§16.4.4):

- «документ в формате PDF, который подписан ЭЦП, **нельзя изменить,
  сохранив действительность подписи**»;
- «**Изменить любую цифровую подпись, которой уже подписан документ ‑
  невозможно**».

Проверка подписи громкая: «Если проверить подписи невозможно ‑ будет
сформировано исключение».

**А вот запись — тихая:** «После того, как в прочитанный документ PDF
внесены изменения ‑ документ необходимо записать на диск. **В противном
случае внесенные изменения будут потеряны**». Забытая запись не даёт
ни ошибки, ни следа.

Ограничения печати перечислены: «Не поддерживается двусторонняя печать»,
«При печати не поддерживается выбор источник бумаги по размеру страницы
PDF» (орфография источника), «Документ не поддерживает прозрачность
(только для формата PDF/A-1)». И «С помощью объекта СтраницаPDF нельзя
установить свойства страницы».

## Регулярные выражения: диалект урезан в двух местах

«Используемый диалект регулярных выражений **не поддерживает именованные
группы** в регулярном выражении» (§16.5.2).

«При замене **не поддерживается возможность указания строки замены в виде
ссылок на группы поисковой строки**».

Номер группы ограничен: «num должно быть числом, которое больше 1
и не больше максимального количества групп захвата в шаблоне (но
не больше **9**)».

**И умолчание, на котором спотыкаются:** «по умолчанию, оператор ^ выдает
совпадение только в самом начале строки поиска» — многострочный разбор
требует явного флага.

## Распознавание речи выключено в двух случаях

«Распознавание речи не поддерживается: ● В том случае, если
информационная база создана в режиме совместимости Версия 8.1»
(§16.6.2.1), и отдельно про память: «ограниченного объема оперативной
памяти 32-разрядных систем может не хватить для загрузки».

## Чего в главе 16 нет

- **DBF, текстовых и табличных форматов.** Глава 17 перечисляет их
  вместе с JSON и XDTO — «DBF (объект XBase), табличные форматы
  MXL/XLS/XLSX/ODS (объект ТабличныйДокумент) и текст (объекты
  ТекстовыйДокумент, Чт…» — но описаны они не здесь. В главе 16 их нет
  ни одного упоминания;
- **выбора между техниками работы с JSON.** Простая, объектная,
  потоковая и работа через XDTO описаны каждая отдельно, критерия выбора
  глава не даёт — есть только раздел «Совмещение техник»;
- **производительности.** Ни для XDTO, ни для JSON, ни для регулярных
  выражений чисел нет;
- **правил, когда какой формат уместен для обмена.** Это система
  стандартов (`std637`, `std701`, `std799` — разбор
  в `exchange-standards.md`), а не руководство.

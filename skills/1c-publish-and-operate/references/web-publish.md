# Публикация: четыре действия, из которых видно одно

**Ищут по словам:** публикация на веб-сервере, `webinst`, `default.vrd`,
виртуальный каталог, `-wsdir`, IIS и Apache, отключить публикацию,
повторная публикация, права на каталог базы, длина URL, OData и IIS,
дистрибутив тонкого клиента, публикация сервисов расширений.

Источник: руководство администратора, раздел «Настройка веб-серверов для
работы с «1С:Предприятием»» (глава 8); ключи `webinst` — приложение 4.

Адресация опубликованных сервисов (`ws`, `hs`, имя файла публикации) —
у соседа `1c-integrations`. Здесь механизм.

## Что на самом деле делает публикация

«Общая схема публикации выглядит следующим образом: ● Выполняется
регистрация модуля обработки запросов (модуля расширения веб-сервера),
соответствующего веб-серверу. ● На веб-сервере регистрируется виртуальное
приложение. ● Создается каталог виртуального приложения, и в нем размещается
файл default.vrd… ● Для пользователей назначаются права на каталог с файлом
базы данных (только для файлового варианта)» (§8.3.1).

**Четыре действия в четырёх разных местах.** Отсюда правило разбора: «у нас
опубликовано» — не одно состояние, а четыре, и сломаться может любое
из них по отдельности.

## `webinst` без прав не останавливается

«При публикации с помощью утилиты webinst пользователю выдается
диагностическое сообщение, но публикация продолжается» (§8.2).

Скрипт выкладки вернёт успех, а работающей публикации не будет.
**Доказательством служит запрос к адресу, а не код возврата утилиты** —
это тот же класс, что и `/CheckModules` без режимов у соседа
`1c-quality-gates`.

## Публикация под Linux переписывает владение чужим каталогом

«В случае публикации файловой информационной базы, для каталога с файлом
информационной базы в качестве группы-владельца устанавливается группа
пользователя, от имени которого работает веб-сервер, а также настраивается
наследование группы-владельца» (§8.3.2.1).

Нажатие «Опубликовать» меняет права **каталога базы**, а не только каталога
публикации. Прежнюю группу-владельца платформа нигде не запоминает —
записать её надо до, а не после.

## «Отключить» сносит каталог вместе с ручными правками

«Кнопка Отключить выполняет удаление приложения из веб-сервера и каталога
публикации, если это необходимо» (§8.3.2.1).

Всё, что дописано в `default.vrd` руками, уезжает вместе с каталогом.

**И `webinst -delete` бьёт по одному имени:** «При удалении публикации
достаточно указания только параметра -wsdir. Остальные параметры могут
указываться для контроля работы» (приложение 4).

Опечатка в `-wsdir` снесёт не ту публикацию, и больше ничего указывать
не требовалось. Остальные параметры в скрипте удаления имеет смысл писать
именно как предохранитель.

## Сервисы расширений в диалоге не видны

«Web-сервисы, которые расположены в подключенных расширениях,
не отображаются в данной таблицы и могут быть опубликованы только
редактированием файла default.vrd вручную» (§8.3.2.2.2; орфография
источника). То же сказано про HTTP-сервисы расширений.

Соединяя это с предыдущим: **дописанное руками уезжает вместе с каталогом
при «Отключить»**. Что происходит с ним при повторной публикации в тот же
каталог, источник не говорит вовсе (см. «Чего в главе 8 нет») — и это само
по себе причина держать копию файла.

## Неверно выбранная версия Apache даёт работающий вид

«В том случае, если система не смогла однозначно определить версию
установленного на компьютере веб-сервера Apache (2.2 или 2.4), в списке
будут присутствовать обе версии веб-сервера… Поэтому неверное указание
версии веб-сервера приведет к неработоспособности публикации» (§8.3.2.2.1).

**Список с двумя версиями — не выбор, а признак того, что платформа сервер
не определила.** Угадали неверно — публикация «прошла», сайт не работает.

## IIS: три умолчания, о которые спотыкаются

**Публикация идёт не туда, куда думают:** «Публикация всегда выполняется
для веб-сайта по умолчанию (Default Web Site) и пула приложений
по умолчанию» — сказано это в общих требованиях главы (§8.2), среди
особенностей работы с IIS, а не в её разделе про IIS.

**URL режется на 260 символах:** «Стандартно IIS ограничивает URL
260 символами» (§8.10.2.4). Для стандартного интерфейса OData этого мало —
«При обращении к стандартному интерфейсу OData URL может быть достаточно
большой длины», и лечится это параметром реестра с перезагрузкой машины.

**Обновление тонкого клиента молча не работает без MIME-типа:** «для
расширения .zip был установлен один из следующих MIME-типов:
application/x-zip-compressed (настройка веб-сервера IIS по умолчанию) или
application/zip (рекомендация IANA)» (§8.10.2).

## Флажок, который выглядит запретом и им не является

У базы-провайдера OpenID флажок «Публиковать доступ для клиентских
приложений» «Отвечает за возможность работы» клиентских приложений,
и источник тут же оговаривает, что он «не оказывает влияния на возможность
интерактивного входа» (§8.8.2).

База со снятым флажком выглядит закрытой и таковой не является.

## Опечатки самого источника, на которые не надо ловиться

Раздел большой и небрежный: §8.4.3.1 называет флажок «Публиковать тонкий
клиент и веб-клиент», которого в описании диалога нет; описание снятого
флажка Web-сервисов приравнено к `enable="true"`, хотя должно быть `false`;
в линуксовых примерах путь к конфигурации Apache набран как `httd.conf`.

Правило то же, что везде в наборе: **имя ключа и имя файла сверяются
с приложением 4 и с живой машиной**, а не переносятся из главы 8 глазами.

## Чего в главе 8 нет

- **что происходит при повторной публикации в тот же каталог** —
  перезаписывается ли `default.vrd` целиком и что делается с дописанным
  вручную. Есть только перечень случаев, когда предлагается перезапустить
  веб-сервер;
- **значений по умолчанию для элементов `default.vrd`** — глава двенадцать
  раз отсылает к его описанию в приложении 3;
- **публикации мобильного приложения** как отдельной сущности: в главе она
  не описана.

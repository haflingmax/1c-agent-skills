# Открытие форм: параметры, режим окна, внешние компоненты

Три стандарта о том, как форма открывается. Область применения: у 741 —
«управляемое приложение, мобильное приложение», у 742 и 700 — «управляемое
приложение».

Само правило «открывать за один вызов» — в `server-calls.md`; здесь про то,
чем форма параметризуется и в каком окне появляется.

## Параметризованные формы (стандарт 741)

**Параметризованную форму не назначают основной** (пункт 1): «В случаях когда
форма требует параметризации при открытии, предназначена для открытия только
при помощи встроенного языка и, как следствие, **не может быть открыта
из пункта меню "Все функции"**, не следует назначать такую форму основной
формой объекта».

**Если других форм нет** (пункт 2): «то следует сделать основной эту
параметризированную форму. В обработчике `ПриСозданииНаСервере` модуля формы
**необходимо проверять параметры формы и, если они не заполнены, вызывать
исключение**. Текст исключения должен указывать пользователю причину,
по которой форма не может быть открыта».

**Параметры объявляют на закладке, а не выуживают из структуры** (пункт 3):
«Параметры формы **следует объявлять явно на закладке `Параметры` редактора
формы**. В таком случае в коде обработчика `ПриСозданииНаСервере` не требуется
проверять наличие свойств у структуры `Параметры`, а сам состав параметров
формы явно задекларирован (поэтому их не требуется восстанавливать, изучая
весь код обработчика `ПриСозданииНаСервере`)».

```bsl
// Неправильно — параметр не объявлен, состав виден только из кода:
Если Параметры.Свойство("ФамилияИмяОтчество", ФамилияИмяОтчество) Тогда
	Объект.Наименование = ФамилияИмяОтчество;
КонецЕсли;

// Правильно — параметр объявлен на закладке «Параметры»:
Объект.Наименование = Параметры.ФамилияИмяОтчество;
```

## Блокирующее или независимое окно (стандарт 742)

**Умолчание платформы** (пункт 1): «при создании форм некоторых типов объектов
(справочников, планов видов характеристик и др.) им устанавливается режим
открытия с блокированием окна владельца (свойство `РежимОткрытияОкна`
установлено в значение `БлокироватьОкноВладельца`)». Смысл умолчания назван:
«предполагается, что работа с ними всегда выполняется "за один заход", без
необходимости переключения в другие формы… рабочее пространство пользователя
не "замусоривается" лишними окнами».

**Когда умолчание меняют** (пункт 2) — «когда форма представляет из себя
"рабочее место", т.е. с помощью неё осуществляется доступ к большому
функциональному блоку». Признаков четыре, и достаточно любого:

- «открытие других самостоятельных форм (отчётов, справочников и т.д.)
  из глобального командного интерфейса приложения»;
- «сравнение двух и более объектов между собой»;
- в панели навигации формы «содержится большое количество переходов
  к связанной информации (например, к подчинённым справочникам)»;
- в панели навигации «есть переходы к параметризируемым отчётам».

Модальность здесь меняется внутри пункта: менять умолчание
**«рекомендуется»**, но «Для таких форм **необходимо** установить свойству
`РежимОткрытияОкна` значение `Независимый`. Как правило, это формы документов».

**Отдельное окно** (пункт 3), для платформы 8.3.9 и ранее: «**не следует**
открывать формы в режиме `ВариантОткрытияОкна.ОтдельноеОкно`, поскольку
в конфигурациях, рассчитанных на работу в режимах "Такси" или "В закладках",
такой режим открытия форм значительно усложняет пользователю настройку
приложения для работы в веб-клиенте».

Исключение оттуда же: «когда в конфигурации предусмотрено, что форма
открывается таким способ **только в тонком клиенте или только в режиме
"В отдельных окнах"**».

## Установка внешних компонент (стандарт 700)

**Установка интерактивна** (пункт 1.1): «Установка внешних компонент
и расширений платформы **должна быть интерактивной**. Пользователь должен
самостоятельно принять решение об установке. В диалоге установки **должно быть
указано, для чего нужна компонента (расширение) и что не будет работать, если
её не устанавливать**».

Неправильная конструкция названа стандартом дословно:

```bsl
// Неправильно — установка без спроса:
Если Не ПодключитьВнешнююКомпоненту(…) Тогда
	УстановитьВнешнююКомпоненту(…)
```

Правильный текст вопроса стандарт тоже приводит: «Для продолжения работы
требуется установить внешнюю компоненту, которая позволит работать
с отчётностью. Для установки компоненты нажмите "Установить". После завершения
установки нажмите "Продолжить"».

**Когда спрашивать** (пункт 1.2): «Рекомендуется выводить предложение
об установки компоненты (расширения) **перед выполнениям прикладного
действия**» — то есть после того, как пользователь нажал «Отправить отчёт»,
а не при запуске программы.

## Список из панели навигации формы объекта (стандарт 684)

Два требования, и оба про то, что контекст уже задан:

- «Список, открываемый из панели навигации формы объекта, следует отражать
  **с отбором по этому объекту**. Например, в списке «Договоры»
  справочника «Контрагент» отражаются договоры только по конкретному
  контрагенту»;
- «В списке **не следует выводить название объекта** (в виде надписи или
  поля ввода в режиме "просмотр"), т.к. оно отображается в области
  системных команд и в панели навигации».

**Второе требование ловит частую привычку** — продублировать «чей это
список» надписью сверху. Стандарт говорит, что место для этого уже занято
платформой.

## Чего в этих стандартах нет

- **признака, по которому видно, что форма уже открыта** в другом окне;
- **что делать с параметром формы, который пришёл неожиданного типа:**
  проверка параметров остаётся на разработчике;
- **механизма самих внешних компонент** — `std700` задаёт интерфейсную сторону
  предложения об установке, а как компонента подключается и чем грозит
  неизолированный режим, разбирает `1c-security`
  (`external-components.md`);
- **модальности как механизма** — она в теле раздела и в свойстве
  конфигурации, а перечня методов, которые ею затронуты, стандарты не дают.

# Загрузка конфигурации в базу

Разбор одной операции по шагам. Состав ключей — из руководства администратора 8.3.27,
приложение 7; проверять команды через `scripts/check-1c-cli.py`.

## Что именно грузим

Три разных источника, три разные команды. Их путают чаще всего.

| Источник | Команда | Когда |
|---|---|---|
| Файл поставки `.cf` | `/LoadCfg <файл>` | получена сборка целиком |
| Каталог XML-выгрузки | `/LoadConfigFromFiles <каталог>` | работа велась в исходниках, есть `Configuration.xml` |
| Расширение `.cfe` | `/LoadCfg <файл> -Extension <имя>` | доработка вынесена в расширение |

Загрузка конфигурации **не равна** обновлению базы. `/LoadCfg` меняет конфигурацию, но
структура данных остаётся прежней до `/UpdateDBCfg`. Пока обновление не выполнено, база
работает на старой структуре.

## Шаг 1. Резервная копия

**`1cv8.exe` надо явно дожидаться.** Он собран как оконное приложение и возвращает
управление немедленно. Запущенный обычным образом, он не создаст ни файлов, ни журнала,
ни кода возврата — и это выглядит в точности как тихий отказ. В PowerShell:

```powershell
$p = Start-Process -FilePath $exe -ArgumentList $args -Wait -PassThru -NoNewWindow
$p.ExitCode
```

Файловая база:

```
1cv8 DESIGNER /F d:/base /DumpIB d:/backup/base-2026-08-21.dt /DisableStartupDialogs /Out d:/log/dump.txt
```

Каталог `d:/backup` должен существовать: платформа промежуточные каталоги не создаёт.

Клиент-серверная — резервная копия делается средствами СУБД, а не `/DumpIB`: выгрузка dt
на большой базе занимает часы и требует монопольного доступа.

## Шаг 2. Сохранить то, что заменяем

```
1cv8 DESIGNER /F d:/base /DumpCfg d:/backup/before.cf /DisableStartupDialogs /Out d:/log/dumpcfg.txt
```

Это дешевле полной резервной копии и достаточно, чтобы вернуть конфигурацию, если новая
окажется неверной. Данные при этом не страдают.

## Шаг 3. Освободить базу

Нужно, если обновление будет полным (`-Dynamic-`) и потребует реструктуризации.

**Клиент-серверная.** Блокировка начала сеансов ставится из консоли кластера или через
`ibcmd`; при непустом коде доступа подключение выполняется с `/UC <код>`:

`ibcmd` поставляется с серверными компонентами. Если установлен только клиент,
его в каталоге `bin` не будет, и этот путь недоступен.

```
1cv8 DESIGNER /S "srv\base" /UC 1234 /LoadCfg d:/new.cf /DisableStartupDialogs /Out d:/log/load.txt
```

Разделитель в `/S` — обратная косая: `<сервер>\<имя базы>`. Это единственное место
в наборе, где прямая косая неверна.

Принудительно завершить сеансы можно самим обновлением:

```
/UpdateDBCfg -SessionTerminate force
```

Значения `<режим>`: `disable` — не завершать принудительно, значение по умолчанию;
`force` — завершать. Завершение сеансов принудительно теряет несохранённую работу
пользователей, поэтому это решение согласуется, а не принимается на месте.

**Файловая.** Достаточно, чтобы никто не держал `1Cv8.1CD`.

## Шаг 4. Загрузка и обновление

Из файла поставки, с полным обновлением:

```
1cv8 DESIGNER /F d:/base /LoadCfg d:/new.cf /UpdateDBCfg -Dynamic- /DisableStartupDialogs /Out d:/log/load.txt /DumpResult d:/log/result.txt
```

Из исходников XML:

```
1cv8 DESIGNER /F d:/base /LoadConfigFromFiles d:/src /UpdateDBCfg -Dynamic- /DisableStartupDialogs /Out d:/log/load.txt /DumpResult d:/log/result.txt
```

Расширение:

```
1cv8 DESIGNER /S "srv\base" /LoadCfg d:/ext.cfe -Extension МоёРасширение /UpdateDBCfg /DisableStartupDialogs /Out d:/log/ext.txt
```

Динамическое обновление — `-Dynamic+`. Оно не требует эксклюзивного доступа, но не проходит
там, где нужна реструктуризация таблиц. Выбор между `-Dynamic+` и `-Dynamic-` делается
заранее и обосновывается, а не подбирается запуском.

## Шаг 5. Проверить результат, а не отчёт

**Отчёт платформы бывает ложным.** Проверено на 8.3.27.2325: команда с выдуманным
ключом `/DumpCfgToFile` вернула `DumpResult` = `0` и записала в `/Out` «Сохранение
конфигурации успешно завершено», **не создав файла**. Оба отчётных канала сказали
«успех», не сделав ничего.

Поэтому успех определяется по результату:

| Что делали | Чем доказан успех |
|---|---|
| выгрузка в файл | файл существует, размер больше нуля |
| выгрузка в XML | каталог содержит `Configuration.xml` |
| загрузка конфигурации | повторная выгрузка даёт файл, отличный от прежнего |
| обновление базы | код возврата 0 и в журнале нет строк об ошибке |

`DumpResult` и `/Out` остаются полезными — но как источник причины отказа,
а не как доказательство успеха.

Опция `/Out <файл> -NoTruncate` не очищает журнал при новом запуске. В пакетном
режиме запись не буферизуется, поэтому журнал можно читать по ходу длинной операции.

## Что делать, когда не вышло

| Симптом | Причина |
|---|---|
| Команда молча ничего не сделала | нет `/DisableStartupDialogs`: платформа ждёт ответа в диалоге |
| Ошибка про несуществующий каталог | промежуточные каталоги пути не созданы заранее |
| Отказ загрузить расширение | расширение подключено к хранилищу конфигурации; сначала отключить |
| Обновление не проходит динамически | изменение требует реструктуризации, нужен `-Dynamic-` и свободная база |
| Не удаётся подключиться к базе | установлена блокировка соединений, нужен `/UC <код>` |

## Откат

Порядок обратный шагам 1 и 2:

1. вернуть конфигурацию из `before.cf` через `/LoadCfg`, затем `/UpdateDBCfg`;
2. если пострадали данные — восстановить базу целиком: `/RestoreIB` для файловой либо
   средствами СУБД для клиент-серверной.

Второй путь теряет всю работу пользователей с момента копии, поэтому первый пробуется раньше.

# Файловая система: временные файлы, права, расширения

Стандарт 542 «Доступ к файловой системе из кода конфигурации», область
применения — «управляемое приложение, мобильное приложение, обычное
приложение». В заголовке на ИТС стоит пометка «(Раздел обновлен!)».

Три запрета раздела 6 — в теле навыка. Здесь остальное: механика временных
файлов, права доступа и проверка того, что приходит с клиента.

## Временные файлы и каталоги (раздел 1)

**Имя берут у платформы** (пункт 1.1): «Для получения имени временного файла
**следует использовать метод `ПолучитьИмяВременногоФайла`** (исключение
составляет веб-клиент, см. п. 1.3). В противном случае возможна некорректная
работа в многопользовательском режиме, возникновение проблем с правами
доступа, **неконтролируемое накопление временных файлов**».

Что даёт платформа взамен — перечислено там же:

- «гарантирует уникальность имени»;
- «обеспечивает доступ к файлу и сохранение контроля над ним»;
- «автоматически удаляет файлы при перезапуске рабочего процесса сервера или
  клиентского приложения, а также **через 20 минут после серверного вызова
  или сеанса**, в котором файлы были созданы (версия платформы **8.3.17
  и выше**)».

**Каталог — тем же методом** (1.2): «Для создания временного каталога также
рекомендуется использовать имя, полученное с помощью
`ПолучитьИмяВременногоФайла`. Внутри созданного каталога можно создавать другие
файлы без ограничений».

**В веб-клиенте метода нет** (1.3): «При выполнении кода веб-клиентом метод
`ПолучитьИмяВременногоФайла` **недоступен**. Для формирования имён временных
файлов **необходимо использовать функцию `КаталогВременныхФайлов` и объект
`УникальныйИдентификатор`**».

**Удалять за собой — самому** (1.4): «После окончания работы с временным файлом
или каталогом его **необходимо удалить самостоятельно**. **Нельзя рассчитывать
на автоматическое удаление** при следующем запуске платформы».

Оговорка пункта 1.1 этому не противоречит: там автоудаление обещано
для перезапуска процесса и для 20 минут после вызова, а не «при следующем
запуске».

**Кластер разрывает работу с файлом** (1.5): «При использовании временных файлов
на сервере **необходимо полностью завершать работу с ними в рамках одного
серверного вызова**. При работе с кластером серверов при следующем вызове файлы
могут стать недоступны, так как код начнёт исполняться на другом компьютере».

Что вместо — названо там же: «Для сохранения данных между серверными вызовами
в пределах сеанса **следует использовать временное хранилище платформы** (методы
`ПоместитьВоВременноеХранилище`, `ПолучитьИзВременногоХранилища`)».

## Права доступа к файлам (раздел 5)

Общее: «доступ к ним ограничен правами пользователя операционной системы,
от имени которого запущено приложение».

- **из клиентского кода** (5.1) — «под правами пользователя, от имени которого
  запущено приложение (тонкий, толстый или веб-клиент). Как правило, это
  текущий пользователь операционной системы»;
- **из серверного кода** (5.2) — «при использовании клиент-серверной
  информационной базы, доступ ограничен правами пользователя, **от имени
  которого запущен сервер 1С:Предприятия**»; «при использовании файловой базы,
  опубликованной на веб-сервере, доступ ограничен правами пользователя,
  **от имени которого запущен веб-сервер**».

Сноска оттуда же: «Рабочие процессы могут быть также запущены от имени другого
пользователя, отличного от того, под которым запускается агент сервера» —
подробности в описании служебного файла `swpuser.ini`.

## Что приходит с клиента (раздел 6, остальное)

**Расширение файла** (6.3): «Если серверный метод использует расширение файла,
переданное с клиента, **рекомендуется воспользоваться одним из вариантов его
проверки на безопасность**: описать на сервере коллекцию со списком допустимых
расширений и проверять, что переданное значение входит в этот список; либо
воспользоваться методом Библиотеки стандартных подсистем
`ОбщегоНазначенияКлиентСервер.ЗаменитьНедопустимыеСимволыВИмениФайла`».

**Путь из данных базы** (6.4): при формировании пути «на основе данных
из информационной базы (например, поле ввода, которое может редактировать
пользователь) рекомендуется воспользоваться» тем же методом БСП.

**Три условия для временного файла** (6.6): «вся работа с файлом выполняется
в рамках **одной процедуры**; путь к файлу получается методом
`ПолучитьИмяВременногоФайла` и **не изменяется**; после использования файл
на диске **удаляется**».

**Профили безопасности** (6.8): «Администраторам информационных баз
**рекомендуется** использовать профили безопасности для ограничения доступа
к файловой системе на сервере».

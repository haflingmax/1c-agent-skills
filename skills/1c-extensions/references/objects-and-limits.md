# Что расширяется у каждого объекта и где границы

**Ищут по словам:** чего нельзя в расширении, изменение типа реквизита
расширением, состав регистра, регистраторы, предопределённые элементы
расширения, перечисление расширения, макет расширения, план обмена
и расширение, подписка на событие в расширении, общий реквизит, нумератор,
регламентное задание в расширении, длина кода, локализуемые реквизиты.

Источники: руководство разработчика, §30.1.3 и §30.4.8–30.4.31.

Три закрытых перечня и транзитивное правило стоят **в теле навыка**; здесь
границы, которые в теле не помещаются, и разбор по видам объектов.

## Запрет на регистры уже, чем читается

В §30.1.3 стоит: «Не поддерживается изменение структуры регистров всех видов.
Поддерживается только расширение состава регистраторов». Прочитанное само
по себе, это значит «регистр расширением не трогать».

Настоящая граница другая. §30.4.22 даёт **закрытый перечень** того, где
разрешено менять Тип, и в нём последним пунктом стоит: «Измерения, ресурсы
и реквизиты для следующих объектов конфигурации: … Регистры сведений. …
Регистры накопления. … Регистры бухгалтерии. … Регистры расчета».

То есть **состав** регистра менять нельзя — новых измерений, ресурсов
и реквизитов не добавить, — а **тип уже существующего** измерения, ресурса
или реквизита расширяется. Широкое чтение запрета отнимает единственный
законный способ дотянуться до регистра.

Та же пара работает и в другую сторону: §30.1.3 запрещает «добавление
реквизитов и табличных частей для: … плана видов характеристик; … плана
счетов; … плана видов расчетов», а §30.4.22 те же три объекта называет среди
тех, у кого тип реквизита расширяется. Запрет — на добавление, разрешение —
на изменение типа.

**Перечень §30.4.22 закрыт для тех объектов, о которых он говорит:** «Для
заимствованных объектов допускается изменение свойства Тип для следующих
объектов»; в нём 25 пунктов, от констант и параметров сеанса до измерений
последовательностей документов.

Читать его как закрытый для **всей** главы нельзя: у внешнего источника
данных тип берётся из расширения по другому правилу — «При расширении
внешнего источника данных, свойства расширяемого объекта полностью получаются
из расширения (в том числе и свойство Тип)» (§30.4.30).

**И два места, где тип не расширяется вовсе:** «Не поддерживается расширение
свойства Тип для следующих объектов конфигурации: … Общие реквизиты,
являющиеся разделителями. … Реквизиты с типами внешних источников данных»
(§30.4.22).

**Расширение типа — это объединение, а не замена:** результирующий тип
обычно становится составным, и «для реквизитов, сохраняемых в базе данных,
результирующий тип не может включать типы, которые не могут входить в состав
составных типов (ХранилищеЗначения, УникальныйИдентификатор и т. д.)»
(§30.4.22).

## Нумерация: правила и их адресаты (§30.4.26)

Здесь важно, **у каких объектов** какое свойство расширяется, — иначе правило
применяют не туда.

«Длина кода» адресована пяти видам объектов, «Тип кода» — только части
из них. Правило разрешения расхождения: «Если в расширяемой конфигурации
и расширении значения свойства Тип кода различаются (для одного и того же
объекта), то в качестве результирующего значения этого свойства будет выбран
тип Строка».

**Длины меняются только вверх**, а при нескольких расширениях побеждает
максимум. Для остальных свойств нумерации — «Позволяем задавать значение
свойства Допустимая длина номера, Периодичность и Контроль уникальности.
Результирующим будет значение из последнего подключенного расширения».

**Локализуемые реквизиты расширяются, и список этим не исчерпывается:**
«В расширении имеется возможность переопределять (расширять) следующие
локализуемые реквизиты объектов конфигурации: заголовок; формат; формат
редактирования; подсказка; … расширенное представление записи». В середину
перечня попадают представления объекта и списка — то самое, ради чего
в перечень и лезут, — и побеждает расширение, применённое последним.

## Отчёты, СКД и макеты

**Подменить схему компоновки можно только через модифицируемое свойство:**
«необходимо добавить отчет в расширение, затем отметить свойство Основная
схема компоновки данных как изменяемое (см. здесь) и затем создать нужную
схему компоновки данных для отчета» (§30.4.8).

**Править чужую схему — значит скопировать её целиком:** «то рекомендуется
скопировать схему компоновки данных из основной конфигурации в расширение,
указать эту схему в качестве основной в заимствованном отчете и затем
модернизировать эту схему» (§30.4.8). Обновлять копию после обновления
типовой придётся руками, и команды для этого источник не называет —
в отличие от макета, где команда есть.

**У табличного документа два способа расширения:** «Команда Способ
расширения позволяет указать, каким образом будет расширяться табличный
документ: объединением расширяемой таблицы и таблицы из расширения (способ
Объединять) или таблица расширения будет целиком…» (§30.4.13). Второй способ
не стирает оригинал безвозвратно: «С помощью команды Показать сохраненную
таблицу можно увидеть расширяемый табличный документ».

Догонять изменения типовой надо руками: «Команда Обновить расширение таблицы
позволяет обновить расширяемый табличный документ в том случае, если он
изменен в расширяемой конфигурации».

## Сервисы и XDTO

**Пакет XDTO берётся из расширения целиком, а не сливается:** «При подключении
расширения, свойство URI пространства имен пакета будет получено
из расширения. … Аналогичное поведение будет с составом пакета XDTO: состав
будет полностью получен из расширения», и при нескольких расширениях
побеждает последнее в списке (§30.4.9). Состав и URI обязаны меняться
синхронно — либо один из них объявляется контролируемым: «Состав пакета
и свойство URI пространства имен должны или одновременно модифицироваться
в расширении, или один элемент пакета может быть модифицированным, а второй,
одновременно, должен быть контролируемым».

**А список пакетов web-сервиса именно дополняется** — «свойство Пакеты XDTO
расширяемого Web-сервиса **дополняется** списком пакетов из модифицированного
одноименного свойства заимствованного Web-сервиса» (§30.4.10). Два соседних
параграфа, две разные механики.

**Дубль имени файла публикации разрешается молча:** «будет использоваться
первый…» (§30.4.10).

**А неуникальный корневой URL HTTP-сервиса валит расширение целиком** —
правило стоит в теле навыка (§30.4.11).

## Предопределённые элементы и перечисления

**Новый предопределённый элемент требует пометки свойства:** «Если для
заимствованного объекта в расширении создан новый предопределенный элемент,
то для свойства Предопределенные заимствованного объекта следует установить
признак модифицируемого свойства» (§30.4.12).

**При заимствовании типы молча урезаются:** «Типы, которые отсутствуют в типе
плана видов характеристик заимствованного объекта при переносе удаляются
из типа элемента» (§30.4.12).

**Что сверяется при подключении** (§30.4.12): «Совпадение имени, кода
и наименования элемента», совпадение родителя — для иерархических объектов,
тип элемента — для планов видов характеристик, и ещё три пункта для плана
счетов: вид счёта, признак забалансовости и состав признаков счёта.

**Перечисления — отдельный узел риска.** Удаление расширения обнуляет ссылки
(правило в теле). Пока расширение не подключено, «такие значения отображается
аналогично ссылки на несуществующий объект» (§30.4.17). А совпадение
внутренних идентификаторов даёт два разных исхода: совпадение идентификатора
**значения** делает реструктуризацию базы невозможной, совпадение
идентификатора **самого перечисления** реструктуризацию не блокирует, но
расширение не подключается (§30.4.17).

## Планы обмена, документы, регистраторы

**Расширение умеет только расширять состав плана обмена:** «Не поддерживается
возможность исключать объекты расширяемой конфигурации из состава плана
обмена. Другими словами, расширение не может уменьшить объем информации,
передаваемой планом обмена» (§30.4.14).

**Собственный план обмена расширения в РИБ не участвует** (§30.4.14),
и «Система не предоставляет инструментов для автоматической синхронизации
состава расширений между узлами обмена данными» (§30.4.14).

**Регистратор и регистр обязаны быть по одну сторону:** документ расширения
«не может выступать регистратором для собственных регистров расширяемой
конфигурации. Также и наоборот» (§30.4.16).

**И отдельным правилом — что документу расширения разрешено:** он «может
выступать регистратором для любого заимствованного регистра расширения,
кроме оборотного регистра накопления с включенным режимом агрегатов»
(§30.4.16).

**Собственному документу расширения недоступны нумераторы
и последовательности** (§30.4.16), а собственным регистрам накопления —
агрегаты (§30.1.3).

## Подписки, общие реквизиты, задания

**Заимствованную подписку можно только дополнить источником**, а обобщённые
типы источника доступны лишь собственным подпискам (§30.4.21).

**Собственный общий реквизит завести нельзя:** «Общие реквизиты могут быть
только заимствованными реквизитами расширения» (§30.4.25). Состав разделителя
при этом становится скрытым условием подключения расширения.

**Заимствованное регламентное задание — только для чтения:** «Заимствованное
регламентное задание не позволяет изменять каких-либо своих параметров»
(§30.4.29).

**У бизнес-процессов карта маршрута заменяется целиком**, а не дополняется
(§30.4.31), и повторное заимствование элементов карты уже заимствованные
не обновляет.

## Чего в этих параграфах нет

- **чем кончится нарушение запрета**, если расширение собрано не мышью:
  перечень проверок при подключении (§30.2.1.1) запретов §30.1.3 не содержит;
- что происходит с сохранёнными вариантами отчёта при подмене схемы
  компоновки (§30.4.8);
- что происходит с данными, ссылающимися на предопределённый элемент
  расширения, при его удалении — для значений перечисления ответ есть,
  для предопределённых нет;
- можно ли отключить или подавить существующую подписку расширяемой
  конфигурации (§30.4.21 говорит только про добавление источника).

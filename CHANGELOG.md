# История версий

Формат — по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — semver по правилам `docs/releasing.md` (до `1.0.0` двигаются
`MINOR` и `PATCH`).

Заведён на версии 0.7.0. До неё релизов не было: манифесты появились
вместе с первым коммитом, а записывать было нечего — основание Н-13
в `docs/reviews/2026-08-23-core-review.md`.

## 0.7.0 — 24.09.2026

**Первая готовая альфа.** Шестнадцать навыков: ядро и все пятнадцать
разделов, раскладка заполнена целиком. Охват набора и его границы
записаны поимённо в `docs/debt.md` — это часть релиза, а не приложение
к нему: набор обещает не изображать раздел, которого нет, и долг
существует затем, чтобы обещание можно было проверить.

### Добавлено

- **Четвёртая опора — документация СУБД.** PostgreSQL 17 и Microsoft Learn
  по SQL Server цитируются наравне с ИТС и сверяются тем же прибором
  (решение 24, этап УГЛУБЛЕНИЕ-БД). Корпус — 29 страниц, базы `pgdoc`
  и `mslearn`.
- **Блокировки и изоляция на уровне СУБД** —
  `1c-queries/references/dbms-locks-and-isolation.md`. Порог эскалации
  у SQL Server в двадцать раз ниже платформенного и считается на оператор
  и таблицу; у PostgreSQL эскалации строковых блокировок нет вовсе.
  Двадцать секунд ожидания ставит платформа, а не СУБД: у обеих СУБД
  умолчание — ждать вечно.
- **Индексы и планы на уровне СУБД** —
  `1c-queries/references/dbms-indexes-and-plans.md`. `ПОДОБНО` на
  PostgreSQL с русской локалью не ложится на обычный индекс: нужен
  специальный класс операторов, и стандарт 658 об этом не знает.
- **Обслуживание и копии СУБД** —
  `1c-publish-and-operate/references/dbms-maintenance-and-backup.md`.
  Две из четырёх команд методички 5837 Microsoft объявила подлежащими
  удалению; `pg_dump` не заменяет непрерывное архивирование; база 1С
  на SQL Server по умолчанию оказывается в полной модели восстановления.
- **Сторона СУБД в технологическом журнале** —
  `1c-quality-gates/references/tech-journal-dbms.md`. Три механизма,
  каждый выключен по умолчанию и у каждого своя цена. Поля плана
  для MS SQL опознаны как колонки `SHOWPLAN_ALL` плюс фактические
  `Rows`/`Executes` из `STATISTICS PROFILE`: план из журнала несёт факт
  рядом с оценкой, и расхождение читается прямо оттуда.
- **Активность движений** — раздел в
  `1c-queries/references/virtual-tables.md`. Виртуальная таблица
  учитывает активность сама, физическая требует `ГДЕ Активность = ИСТИНА`
  (стандарт 633), а срез последних меняет состав в зависимости от режима
  совместимости, и признака в тексте запроса нет.
- **`docs/debt.md`** — чего набор не покрывает, с адресами, по четырём
  классам плюс раздел «вне охвата по решению владельца».
- **`CHANGELOG.md`** — этот файл.

### Исправлено

- **Собственное ложное отрицание про блокировки СУБД.** Набор утверждал,
  что соответствия блокировок 1С и СУБД не увидеть. ИТС описывает
  и механизм, и свойства: элемент `<dbmslocks>` и параграф §3.24.5.
  Утверждение сужено до того, чего действительно нет.
- **Маршрут `1c-quality-gates` на вопрос о плане запроса СУБД.** Раздел
  не поднимался, и ответ противоречил набору. В описание добавлен повод;
  перемер: не пройдено → по набору.
- **Прибор мерил не то.** Codex читает навыки из
  `%USERPROFILE%\.agents\skills`, а установщик туда не клал — копия
  оставалась от 22.09. Четыре прогона показали «раздел не поднялся»
  на файлах, которых не существовало. Установщик получил третью цель,
  а `tools/run-prompt.ps1` теперь сверяет копию среды с репозиторием
  и отказывается запускаться на устаревшей.

### Известные ограничения

Полный список — `docs/debt.md`. Коротко:

- поведение СУБД выведено из документации и **запуском не проверено**
  (живой СУБД у набора нет);
- отличия сборок PostgreSQL «…1C» не описаны ни документацией, ни ИТС
  дальше настроек;
- четыре инструмента по схеме компоновки данных запланированы
  и не написаны;
- бюджет описаний каталога занят на 90 % — следующие поводы маршрутизации
  придётся менять местами, а не дописывать;
- вне охвата по решению владельца: БСП, обычное приложение, мобильная
  разработка, Db2 и Oracle, правила под конкретные типовые конфигурации.

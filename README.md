# Навыки ИИ-агентов для разработки на 1С:Предприятие 8.3

Набор навыков (Agent Skills) для работы с исходниками конфигураций 1С: метаданные,
управляемые формы, запросы, права, расширения, обновление и поддержка.

**Охват.** Платформа 8.3 любой подверсии и общие вопросы разработки — то, что одинаково
верно для любой конфигурации. Правил под конкретную типовую конфигурацию набор не содержит:
соглашения ЕРП, БП и ЗУП различаются между собой и меняются от релиза к релизу, поэтому им
место в отдельных наборах, а не в этом.

**БСП тоже вне охвата.** Библиотека стандартных подсистем есть почти в любой
конфигурации, но живёт своим циклом версий, и её API между ними расходится. Общий совет,
выданный за правило БСП, верен не для всякой версии — поэтому специфика библиотеки
пойдёт отдельным набором. Ядро умеет распознать БСП и сказать, что она вне охвата,
вместо того чтобы выдумывать её API.

Формат — открытый стандарт [Agent Skills](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview):
папка с `SKILL.md`. Поэтому набор годится для любой среды, которая этот стандарт
поддерживает. Запуском проверены три: Claude Code, Kilo Code и Codex (у последнего —
с оговоркой Д-11, см. «Особенности сред»). Cursor, Copilot и Gemini поддерживают формат
по своей документации, но нами не проверялись.

## Установка

Два пути. Первый предпочтителен: плагин обновляется сам, копии вручную — нет.

### Как плагин через маркет (обновляется автоматически)

**Claude Code:**

```
/plugin marketplace add haflingmax/1c-agent-skills
/plugin install 1c-agent-skills@haflingmax-1c
```

Маркет — это сам репозиторий. Обновления приходят при обновлении маркета, ставить заново
не нужно.

**Codex:** репозиторий несёт `.codex-plugin/plugin.json` с указанием на `./skills/`, поэтому
подключается как плагин Codex:

```
codex plugin marketplace add haflingmax/1c-agent-skills
codex plugin add 1c-agent-skills@haflingmax-1c
```

Либо через обозреватель: `codex /plugins`.

### Отдельными навыками, без плагина

Если плагины не используются — скопировать содержимое `skills/` в каталог навыков среды.

| Среда | Глобально | В проекте | Проверено запуском |
|---|---|---|---|
| Claude Code | `~/.claude/skills/` | `.claude/skills/` | глобальный путь — да; проектный — нет |
| Kilo Code | `~/.config/kilo/skills/` | `.kilo/skills/` | глобальный путь — да; проектный — нет |
| Codex | `~/.agents/skills/` | `.agents/skills/` | глобальный путь — да; проектный — нет |
| Copilot, Gemini | `~/.agents/skills/` | `.agents/skills/` | **нет, только по документации** |
| Cursor | `~/.cursor/skills/` | `.cursor/skills/` | **нет, только по документации** |

Колонка «Проверено запуском» — не формальность. «Да» означает, что набор туда положен
и агент в этой среде поднял навык: `~/.claude/skills/` и `~/.config/kilo/skills/` —
`tools/install-skills.ps1` плюс замер срабатывания
([docs/evidence/2026-08-22-trigger-rate.md](docs/evidence/2026-08-22-trigger-rate.md)),
`~/.agents/skills/` — приёмка
([docs/evidence/2026-08-22-acceptance.md](docs/evidence/2026-08-22-acceptance.md)).

Остальные ячейки взяты из документации соответствующих сред и **прогоном не
подтверждены**: Copilot, Gemini и Cursor на машине разработки набора недоступны,
проектные каталоги не проверялись ни в одной среде. Пути в них правдоподобны, но
это утверждение о чужой среде, а не наш замер — если у вас не подхватилось,
дело может быть в них, а не в наборе.

```powershell
Copy-Item skills/* "$env:USERPROFILE/.claude/skills/" -Recurse -Force
```

При таком способе обновлять придётся вручную, повторным копированием.

### Проверить, что подхватилось

```powershell
kilo debug skill          # Kilo
```

В Claude Code — `/plugin` покажет установленные плагины и их навыки.

## Устройство

Разделы разрезаны **по области знания разработчика**, а не по типу файла и не по команде.

Это осознанный выбор. В известных наборах навыков по 1С один тип объекта даёт шесть навыков —
`meta-compile`, `meta-decompile`, `meta-validate`, `meta-info`, `meta-edit`, `meta-remove`, — и
их описания различаются одним глаголом. Человеку, который зовёт команду по имени, так удобно.
Агент, выбирающий навык сам по описанию, между ними осмысленно выбрать не может.

Здесь раздел отвечает на вопрос «что я сейчас делаю»: правлю форму, пишу запрос, настраиваю
права. Операции внутри раздела остаются операциями.

Обоснование раскладки и правила для новых поднавыков —
в [`skills/developing-1c-configurations/references/architecture.md`](skills/developing-1c-configurations/references/architecture.md).

## Режимы работы

Набор работает тремя способами, и ни один из них не требует ничего доустанавливать.

**Разовая задача.** «Напиши запрос по остаткам», «сделай обработку выгрузки» — навык
срабатывает сам, доменные правила применяются, никакой церемонии не навязывается.

**Операция с платформой.** «Загрузи конфигурацию в базу» — не код и не планирование, а
последовательность команд с развилками: файловая база или клиент-серверная, нужен ли простой
пользователей, допустимо ли динамическое обновление. Ошибка здесь дороже, чем в коде,
поэтому порядок описан рецептом, а состав ключей проверяется скриптом.

**Внутри конвеера планирования.** Если работа идёт через brainstorming и документ плана,
решения, которые нельзя исправить правкой кода, попадают в план, а не всплывают на реализации.
Набор ничего для этого не требует: признак — готовится ли документ плана, а не установлен ли
конкретный плагин.

Набор навыков **superpowers** рекомендуется, но не обязателен:
он даёт готовый конвеер brainstorming → план → реализация, в который набор встраивается.
Зависимостью он не объявлен намеренно — формат плагинов не знает мягких зависимостей, а
жёсткая выключила бы весь набор целиком, включая два режима, которым конвеер не нужен.

### Особенности сред

| Среда | Что работает |
|---|---|
| Claude Code | все три режима |
| Codex | не проверено на официальной модели; на связке с minimax-m3 через адаптер открыт Д-11 — автозагрузка навыка падает, 0 из 5 предпринятых прогонов ([docs/evidence/2026-08-22-acceptance.md](docs/evidence/2026-08-22-acceptance.md), [docs/plan.md](docs/plan.md)) |
| Kilo Code | разовые задачи и операции с платформой |

В Kilo конвеер с подагентами не запускается, если в конфигурации закрыт инструмент `task` —
а закрывают его часто и осознанно. Доменные правила при этом работают полностью: план
проговаривается в переписке и подтверждается человеком, вместо того чтобы уезжать в документ.

Чтобы навык мог читать свои файлы, каталогу навыков Kilo нужно разрешение на чтение:
правила `read` и `external_directory` по умолчанию закрывают `~/.config/kilo/**`.

## Проверка навыков

Набор несёт четыре проверяльщика с кодом возврата. Каждый возвращает ненулевой код при
нарушении — их можно ставить в CI, и все четыре обязаны быть зелёными перед коммитом.

```powershell
python tools/check-skills.py      # устройство навыка по спецификации Agent Skills
python tools/check-sources.py     # утверждения о необратимости несут источник
python tools/check-manifests.py   # манифесты плагинов и фронтматтер настоящим YAML
python tools/check-quotes.py      # каждая цитата в «ёлочках» стоит в выгрузке ИТС дословно
```

И один прибор без кода возврата — он показывает человеку, а не запрещает:

```powershell
python tools/check-coverage.py --навык 1c-update-and-support --главы 36 37 38
```

Он сверяет подзаголовки руководства разработчика с текстом навыка и печатает,
**сколько рассмотрено**, а не только сколько найдено: ноль находок у прибора,
до которого не дошёл вход, выглядит так же, как ноль находок у полного покрытия.

`check-skills.py` проверяет требования Anthropic к устройству навыка: ограничения на `name`
и `description`, третье лицо в описании, размер тела, глубина ссылок, отсутствие полей вне
спецификации, прямые косые в путях.

`check-manifests.py` закрывает то, чего первый не видит по построению: контракт плагина
Codex (`.codex-plugin/plugin.json` — поля, которые официальный валидатор отвергает),
совпадение версий и описаний двух манифестов, и разбор фронтматтера `SKILL.md`
**настоящим `yaml.safe_load`**, а не регуляркой. Регулярка проходит мимо двоеточия внутри
описания, которое YAML считает началом вложенного отображения.

### Зависимости

Сами навыки не требуют ничего: `SKILL.md`, справочники и `check-1c-cli.py`
обходятся стандартной библиотекой Python. Переменных окружения тоже не требуется.

**Про кодировку вывода.** В окне консоли Python на Windows печатает через
`WriteConsoleW` и отдаёт UTF-8 при любой кодовой странице — проверено запуском
25.08.2026 под `chcp 866`, `1251` и `65001`. А вот при **перенаправлении**
вывода в файл или в трубу Python берёт ANSI-кодировку системы, и первый же знак
вне неё роняет скрипт трассировкой вместо отчёта: так `check-1c-cli.py` падал
на `UnicodeEncodeError`, а `tools/its-search.py` не мог отдать даже `--help`.

С 25.08.2026 скрипты набора сами переводят перенаправленный вывод в UTF-8,
сохраняя обработчик ошибок потока. Если вам нужна другая кодировка — задайте
`PYTHONIOENCODING`, и скрипт не станет её переопределять.

Пакеты нужны только тем, кто дорабатывает набор:

```powershell
pip install pyyaml pytest beautifulsoup4
```

- `pyyaml` — `tools/check-manifests.py` и `tests/test_check_manifests.py`. Без него
  `python -m pytest tests/ -q` не соберётся вовсе (код 2, `ImportError: No module named
  yaml`), а сам проверяльщик упадёт на импорте;
- `pytest` — регресс в `tests/`;
- `beautifulsoup4` (импортируется как `bs4`) — `tools/fetch-vendor-docs.py`: выгрузка документации СУБД
  (решение 24) вынимает из страницы текст статьи. Нужен только тому, кто обновляет
  корпус `_vendor/`; сам набор без него работает.

Список сторожит `tests/test_tools_write_guard.py`: новая внешняя зависимость роняет
прогон, пока не названа здесь.

Правило набора: **любой инструмент, который пишет в `skills/`, заканчивается прогоном
`tools/check-manifests.py` и падает при ненулевом коде.** Так устроены
`tools/build-cli-keys.py` и `tools/measure-trigger.ps1`; сторожит правило
`tests/test_tools_write_guard.py`.

# УГЛУБЛЕНИЕ-БД: проект этапа

**Дата:** 22.09.2026. **Основание:** решение 19 (этап нужен), решение 24
(как его вести). Статус: проект, ждёт утверждения владельцем.

## Зачем

Набор опирается на стандарты 1С, а по работе с базой данных они «крайне
общие»: обобщают, чтобы читатель не ошибся, а не объясняют, что происходит
(решение 19). Живые прогоны 22.09.2026 показали цену: агент без раздела
уверенно выдумывает поведение платформы и СУБД, а с разделом — правильно
называет правило, но дальше стандарта не идёт.

Этап — **критический пересмотр написанного**, а не дописывание. Каждое
утверждение набора о базе данных проверяется вопросом: верно ли оно
на уровне СУБД, или это упрощение, которое в каком-то случае становится
неверным.

## Решения владельца (решение 24)

- **Четвёртая опора** — официальная документация PostgreSQL и Microsoft Learn
  по SQL Server. Цитаты дословно и с адресом, как у ИТС.
- **Охват** — PostgreSQL и MS SQL Server; файловый вариант там, где он
  ведёт себя иначе. Db2 и Oracle — вне этапа.
- **Живой СУБД нет** — поведение СУБД запуском не проверяется, и это
  пишется при утверждении.

## Что пересматривается

**147 единиц с пометкой «БД»** из `docs/closure.md` — готовый список
решения 19. По разделам: `1c-queries` 33, `1c-code-conventions` 23,
`1c-metadata-objects` 22, `1c-reports-and-layouts` 13, `1c-client-server` 12,
`1c-build-and-db` 8, `1c-access-rights` 6, `1c-security` 6,
`1c-extensions` 5, `1c-localization` 5, `1c-managed-forms` 4, по 3 —
`1c-integrations`, `1c-publish-and-operate`, `1c-update-and-support`,
1 — `1c-quality-gates`.

Порядок — по цене ошибки, а не по разделам:

1. **Транзакции, блокировки, изоляция.** `data-mechanics.md`,
   `transactions-and-locks.md`: что платформа просит у СУБД в каждом режиме,
   что такое Read Committed Snapshot у MS SQL и MVCC у PostgreSQL, откуда
   берутся взаимоблокировки и эскалация на стороне СУБД.
2. **Запрос и его план.** Виртуальные таблицы, соединения, индексы
   в условии, временные таблицы, `ВЫРАЗИТЬ`, составные типы: во что это
   превращается в SQL, где СУБД не может использовать индекс.
3. **Эксплуатация СУБД под 1С.** Резервное копирование и восстановление,
   обслуживание статистики и индексов, параметры, которые 1С требует
   от СУБД, — в `1c-publish-and-operate`.
4. **Диагностика.** Техножурнал `DBMSSQL`/`DBPOSTGRS`, план запроса,
   средства СУБД — в `1c-quality-gates`.
5. **Остальные единицы** — по ходу, в порядке разделов.

## Метод

По каждой единице три шага, и каждый оставляет след:

1. **Что набор утверждает** — выписка с адресом в наборе.
2. **Что на уровне СУБД** — выписка из документации СУБД и из методических
   материалов ИТС по производительности (в них MS SQL упоминается в 71
   статье, PostgreSQL — в 36).
3. **Вердикт:** верно / упрощение, которое в названном случае неверно /
   пропущен механизм. Правится только то, что не «верно».

Находки идут в существующие справочники; новый справочник заводится,
только если тема не помещается ни в один (правило 9 архитектуры: бюджет
каталога — 86,2 %, новых навыков этап не заводит).

## Источники СУБД: как цитировать и чем проверять

**Корпус.** `check-quotes.py` сверяет цитаты с выгрузкой ИТС; для СУБД
выгрузки нет. Первая задача этапа — **локальный корпус документации СУБД**
(`_vendor/`): страницы, на которые ссылается набор, выгружаются
и включаются в `its-search.py` и `check-quotes.py` как базы `pgdoc`
и `mslearn`. Без этого цитата из документации СУБД — утверждение без
проверки, а набор такие не принимает.

**Язык.** Документация на английском. Цитата приводится дословно
на языке оригинала, рядом — пересказ по-русски, помеченный как пересказ.

**Версии.** В ИТС фигурируют сборки PostgreSQL 16 и 17 «…1C» — **сборки
с патчами 1С**, и официальная документация PostgreSQL их отличий
не описывает. Поэтому при каждом утверждении о PostgreSQL указывается
версия документации, а где поведение сборки 1С может отличаться, — это
говорится. Для SQL Server — версии, поддерживаемые 8.3.27 по системным
требованиям ИТС.

**Без живой СУБД.** Справочники этапа несут в шапке строку: поведение СУБД
описано по документации, запуском не проверено. Отдельные утверждения
этого не повторяют.

## Задачи

1. **Корпус СУБД и сверка цитат** — выгрузка, базы `pgdoc`/`mslearn`
   в поиске и в `check-quotes.py`, тесты. Прибор прежде письма.
2. **Опись:** 147 единиц → где каждая стоит в наборе сейчас (файл, раздел)
   и её приоритет. Единица без места — это пробел, он пишется отдельно.
3. **Заход 1** — транзакции, блокировки, изоляция.
4. **Заход 2** — запрос и план.
5. **Заход 3** — эксплуатация СУБД.
6. **Заход 4** — диагностика.
7. **Заход 5** — остальное.
8. **Живая проверка на агентах** (не на СУБД): промпты на главные находки
   каждого захода в трёх средах, по той же мере, что 22.09.2026.
9. **Итог:** карта, план, список отсутствий.

После каждого захода: `check-quotes`, `check-skills`, `check-map-promises`,
полный набор тестов, коммит только своих путей.

## Риски

- **Тела разделов у потолка.** Десять тел из шестнадцати стоят в десятке
  токенов от 5000. Всё новое — в справочники; тело правится, только если
  находка меняет правило, и тогда за счёт сжатия прозы.
- **Сборки PostgreSQL для 1С.** Документация PostgreSQL может описывать
  поведение, которое патч 1С меняет. Где ИТС говорит о сборке — ИТС главнее.
- **Объём документации СУБД.** Выгружается не всё, а только страницы,
  на которые ссылается утверждение; корпус растёт вместе с набором.
- **Выдуманное сходство.** «В PostgreSQL так же, как в MS SQL» — самая
  дешёвая ошибка этапа. Каждое утверждение — отдельно по каждой СУБД.

## Чего этап не делает

- Db2, Oracle, углублённый файловый вариант.
- Настройку ОС и железа под СУБД сверх того, что требует 1С.
- БСП — вне охвата набора, как и прежде.
- Живую проверку СУБД — по решению 24.

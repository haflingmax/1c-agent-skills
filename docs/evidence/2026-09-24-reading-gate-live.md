# Живая проверка ворот чтения

**Дата:** 24.09.2026. Задача 6 плана `2026-09-24-reading-gate.md`.
Воспроизводится задача инцидента 28.08.2026 — «Загрузи конфигурацию
в базу данных» в репозитории выгрузки `trade`, без подсказок.

Мера — три критерия успеха из спеки, и третий не мягче первых двух.

## Критерий 1: в Claude Code команда отклонена до запуска

**Не проверен живым прогоном, и это ограничение самого замера, а не итог.**

Хуки Claude Code загружаются только из **установленного плагина**.
`tools/install-skills.ps1` копирует навыки в `~/.claude/skills` — другой
путь, хуков там нет. Плагин в маркете стоит версии 0.7.0; ворота лежат
в неотправленной ветке `feat/reading-gate` под версией 0.8.0.

Что вместо сквозного прогона:

| Проверка | Итог |
|---|---|
| девять модульных тестов решения хука | пройдены |
| ручной прогон шима с настоящим payload команды инцидента | отказ, `permissionDecision: deny`, в причине `[ошибка K002] не указан режим запуска` |
| ручной прогон шима с `git status` | пустой вывод, код 0 — пропуск |
| JSON отказа | чистый ASCII, декодируется в верную кириллицу |

Закрыть критерий можно только публикацией 0.8.0 и установкой плагина
из маркета. До тех пор утверждение «Claude Code отклоняет» остаётся
выведенным из тестов, а не снятым с живой среды.

## Критерий 2: в Kilo и Codex выбирается обёртка

**Выполнен в обеих средах.**

| | Навык | Обёртка в журнале | Проверяльщик | Вопросов |
|---|---|---|---|---|
| Kilo | `1c-build-and-db` | `python scripts/run-1c.py` | 2 упоминания | 0 |
| Codex | `1c-build-and-db` | `python scripts/run-1c.py`, 14 упоминаний | 8 упоминаний | 30 |

Обе среды подняли раздел и собрали команду через обёртку, а не голым
`1cv8`. В журнале Kilo видно и `--ответ` — то есть прочитан и тот кусок
тела, где сказано, о чём прибор спрашивает, а не догадывается.

Сравнение с замером **до** правок (24.09.2026, тот же промпт, тот же
репозиторий): Kilo поднимал раздел и собирал голую команду `1cv8 DESIGNER
…`, обёртки не существовало. Сейчас собирается вызов обёртки.

## Критерий 3: ворота не мешают законному

**Выполнен.** В журналах обоих прогонов — ноль отказов: ни одного
`permissionDecision`, ни одной строки «не прошла проверку». Ни одна
законная команда не задета.

Это не случайность конкретного прогона: арбитром «похоже ли на запуск
1cv8» служит проверяльщик, а не регулярка, и на чужой инструмент он
отвечает K017 с нулевым кодом. Под тестом три случая — `grep 1cv8
log.txt`, `git status`, и запуск самой обёртки (её команда содержит
подстроку `1cv8` внутри кавычек).

## Что подтвердилось попутно

**Сторож свежести копий сработал штатно.** Перед прогонами
`install-skills.ps1` поставил навыки во все три среды; `run-prompt.ps1`
не отказал ни разу — копии совпали с репозиторием. Механизм заведён
24.09.2026 после того, как Codex двое суток читал копию от 22.09.

## Ошибка замера, которую надо записать

Первый прогон Codex развалился: я запустил его одновременно с Kilo
в одном каталоге, и обе среды писали `run.log` туда же —
`The process cannot access the file … because it is being used by another
process`. Прогон переделан последовательно.

Это не дефект набора, а дефект порядка работы: `run-prompt.ps1` кладёт
журнал в рабочий каталог прогона, и два одновременных прогона в одном
каталоге несовместимы по построению. Записано, чтобы следующий раз
не выяснять заново.

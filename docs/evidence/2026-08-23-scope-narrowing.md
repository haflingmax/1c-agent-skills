# Сужение охвата: правка описания и проверка срабатывания (2026-08-23)

Решение 17 общего плана сузило охват набора: только платформа 8.3 и только общие
вопросы разработки. Описание ядра обещало обратное — «соответствовать стандартам
1С **и соглашениям типовых конфигураций**», — и было исправлено.

## Что изменилось в описании

| | |
|---|---|
| Было | `…должен соответствовать стандартам 1С и соглашениям типовых конфигураций, а не общему знанию языка…` |
| Стало | `…должен соответствовать стандартам разработки 1С, а не общему знанию языка…` |

Убрано 33 знака. Перечень предметов (`справочник, документ, регистр, форма,
запрос, отчёт, обработка, роль, расширение, БСП, СКД, файлы .bsl, .epf, .cf`)
не тронут: он и делает основную работу по срабатыванию.

## Чем проверено

Официальными валидаторами — все четыре чистые:

| Проверка | Результат |
|---|---|
| `claude plugin validate .` | Validation passed |
| Codex `validate_plugin.py .` | Plugin validation passed |
| `quick_validate.py skills/developing-1c-configurations` | Skill is valid! |
| `quick_validate.py skills/1c-build-and-db` | Skill is valid! |

`quick_validate.py` при запуске без `PYTHONUTF8=1` падает на `UnicodeDecodeError`
в cp1251 — он читает файл системной кодовой страницей. Это его особенность,
а не дефект наших файлов: с принудительным UTF-8 обе проверки проходят.

Своими проверяльщиками: `check-skills.py`, `check-sources.py`,
`check-manifests.py` — по нулям; 282 теста зелёные.

## Прогон срабатывания

**Это проверка на вменяемость, а не замер.** Полный замер
(`docs/evidence/2026-08-22-trigger-rate.md`) — шесть формулировок в двух средах
на двух срезах, 24 прогона. Здесь сделано два прогона в одной среде:

| Среда | Задача | Ожидалось | Навык |
|---|---|---|---|
| Kilo | «Добавь справочник Договоры.» | сработает | **True** |
| Kilo | «Напиши запрос к MS SQL по остаткам товаров на складе.» | не сработает | **False** |

Журналы: `%TEMP%/1c-run/3b523ac4/run.log`, `%TEMP%/1c-run/62129f57/run.log`.
Мера — структурное событие `tool_use` с `tool == "skill"` в JSON-выводе
`kilo.exe run --format json`, а не поиск подстроки.

**Чего эти два прогона не доказывают.** Что доля срабатывания не изменилась:
для этого нужны все шесть формулировок в обеих средах. Известно лишь, что навык
не перестал подниматься на своей задаче и не начал подниматься на чужой.
Полный перезамер не делался — правка убрала 33 знака из середины описания,
не тронув перечень предметов, и цена ошибки здесь мала: срабатывание
проверяется заново при следующем релизном замере.

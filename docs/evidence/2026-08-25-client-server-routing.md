# Проверка маршрута: 1c-client-server

**Дата:** 25.08.2026. Среда — claude, установка через `tools/install-skills.ps1`.

## Задача

> Заведи регламентное задание, которое раз в пять минут выгружает изменённые
> заказы во внешнюю систему. Функциональность включается функциональной опцией
> ИспользоватьОбменСМаркетплейсом.

## Результат

Навык поднялся: `developing-1c-configurations`, **`1c-client-server`**,
`1c-metadata-objects`, `1c-code-conventions`. Вопросов не задано — задача
самодостаточна, решений владельца в ней нет.

## Что применилось

- **std540 пп. 3.1 и 3.2 — оба сразу.** Признак `Использование` снят
  и управляется опцией; в начале обработчика стоит проверка
  `ПолучитьФункциональнуюОпцию` с `ВызватьИсключение`. Навык сам объяснил,
  зачем оба: «включить задание можно через консоль кластера, минуя опцию.
  Первое экономит ресурсы, второе не даёт выполниться выключенной
  функциональности. Один без другого дыряв»;
- **std402, нижний предел.** Пять минут — `ПериодПовтораВТечениеДня = 300`,
  выше запрета «ни в каких случаях меньше одной минуты»;
- **std540 п. 4.1 применён с разбором, а не механически.** `Предопределённое`
  оставлено `true` — потому что выполнение задания не зависит от данных ИБ;
  пункт 4.1 требует отключать признак для заданий, параметризуемых объектами
  базы (обмен с каждым узлом по своему расписанию).

## Неочевидное следствие, выведенное навыком

Регламентное задание **нельзя включить самой функциональной опцией**: в состав
ФО задания не входят, только константы, реквизиты и команды. Отсюда конструкция
«опция → константа → `ПриЗаписи` модуля менеджера значения константы двигает
`Использование` задания» — ровно та, что стандарт 540 п. 3.1 показывает для
конфигураций без БСП.

Это не переписанное правило, а вывод из него, сделанный под задачу.

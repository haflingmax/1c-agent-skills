# Доказательство блокирующих правил запуском (2026-08-22)

Платформа: `C:/Program Files/1cv8/8.3.27.2325/bin/1cv8.exe`.
База: `D:/1C/base/trade` (файловая, одноразовая).
Скрипт: `tools/prove-blocking-rules.ps1`, запуск `1cv8.exe DESIGNER` через
`Start-Process -Wait` (без ожидания процесс — оконное приложение — возвращает
управление мгновенно, ничего не создав; это выглядело бы как тихий отказ).

## Результат прогона

| Имя        | КодВыхода | DumpResult | ФайлСоздан | Журнал                                    |
|------------|-----------|------------|------------|--------------------------------------------|
| канон      | 0         | 0          | True       | Сохранение конфигурации успешно завершено |
| строчными  | 0         | 0          | True       | Сохранение конфигурации успешно завершено |
| выдуманный | 0         | 0          | False      | Сохранение конфигурации успешно завершено |

## Вывод

- **Блокировка `/DumpCfgToFile` обоснована.** Платформа принимает ключ без ошибки
  (`КодВыхода 0`, `DumpResult 0`), пишет в журнал «Сохранение конфигурации успешно
  завершено» — и при этом файл `.cf` не создаётся (`ФайлСоздан False`). И
  `DumpResult`, и `/Out`-журнал в этом случае врут: успех определяется только по
  факту появления файла на диске, как и требует глобальное ограничение брифа.
  Правило проверяльщика, блокирующее `/DumpCfgToFile` как противоречащее
  документированному составу приложения 7, подтверждено запуском.

- **Блокировка по регистру ключа не обоснована.** И канонический `/DumpCfg`, и
  строчный `/dumpcfg` одинаково создают файл конфигурации (`ФайлСоздан True` в
  обоих случаях). Платформа 8.3.27.2325 нечувствительна к регистру этого ключа —
  значит, правило, которое блокировало бы вариант в нижнем регистре, блокировало
  бы работающий вызов, и его накладывать нельзя.

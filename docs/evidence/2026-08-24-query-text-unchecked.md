# Текст запроса штатные проверки не видят: прогон

Раздел `1c-queries` в разделе «Проверка» утверждает, что офлайн-проверки
синтаксиса запроса платформа не даёт. Утверждение попало в поставляемый текст
на основании поиска по корпусу документации — то есть на основании ненайденного,
а «ненайденное не равно отсутствующему».

Здесь оно проверено запуском.

## Прогон 24.08.2026

Платформа `C:/Program Files/1cv8/8.3.27.2325/bin/1cv8.exe`. Рабочая база
пользователя не трогалась: работа шла на копии `D:/1C/base/trade` в scratchpad,
той же оснастке, что и в `2026-08-24-checkconfig-verdict.md`.

В общий модуль конфигурации положен **синтаксически безупречный код**
со **сломанным текстом запроса** внутри строкового литерала:

```bsl
Процедура СделатьЧтоТо() Экспорт

	Запрос = Новый Запрос;
	Запрос.Текст = "ВЫБРАТЬ ИЗ ГДЕ КОГДА ВЫБОРКА НЕСУЩЕСТВУЮЩАЯ.Таблица ПОДОБНО";
	Результат = Запрос.Выполнить();

КонецПроцедуры
```

Текст запроса здесь не просто неоптимален — он не является запросом: предложения
идут в бессмысленном порядке, таблица не существует, `ПОДОБНО` оборван.

| Шаг | Код | `DumpResult` | Журнал |
|---|---:|---:|---|
| `/LoadConfigFromFiles` | 0 | 0 | пусто |
| `/UpdateDBCfg` | 0 | 0 | «Обновление конфигурации успешно завершено» |
| `/CheckConfig` со всеми пятью тестами | 0 | 0 | **«Ошибок не обнаружено»** |
| `/CheckModules -ThinClient -Server` | 0 | 0 | **«Синтаксических ошибок не обнаружено!»** |

Контроль, что оснастка вообще способна давать красный: тот же прогон на модуле
с вызовом несуществующей процедуры даёт код 101 и три находки по средам
исполнения (`2026-08-24-checkconfig-verdict.md`). Значит ноль здесь — не немота
инструмента, а его ответ.

## Как воспроизвести

Оснастка жила в scratchpad и не сохранена намеренно — она одноразовая, и своего
места в `tools/` не заслуживает (решение 18: не заводить инструмент без реальной
нужды). Но её сборка нетривиальна, поэтому порядок записан здесь.

1. Скопировать файловую базу целиком (каталог с `1Cv8.1CD`) — работать только
   на копии.
2. Выгрузить конфигурацию в XML:
   `DESIGNER /F <копия> /DumpConfigToFiles <кат> /DisableStartupDialogs /Out <лог>`.
3. Пустая конфигурация даёт только `Configuration.xml` и каталог `Languages`.
   Чтобы получить модуль, добавляется общий модуль: файл
   `CommonModules/ТестовыйМодуль.xml` и `CommonModules/ТестовыйМодуль/Ext/Module.bsl`,
   плюс строка `<CommonModule>ТестовыйМодуль</CommonModule>` в `ChildObjects`
   корневого `Configuration.xml`.

   Пространства имён и `version` берутся **из живой выгрузки**, а не из памяти;
   в выгрузке 8.3.27 это `version="2.20"`. Состав `ChildObjects` у пустой
   конфигурации не пуст — там уже лежит `<Language>Русский</Language>`, и модуль
   ставится после него.

   Все файлы 1С пишутся в UTF-8 **с BOM** и с CRLF.
4. Загрузить и обновить:
   `/LoadConfigFromFiles <кат>`, затем `/UpdateDBCfg`.
5. Прогнать проверки с `/DisableStartupDialogs /Out <лог> /DumpResult <код>`.

Скрипт запуска — обычный `Start-Process` с ожиданием по таймауту (`1cv8.exe`
собран как оконное приложение и без ожидания возвращает управление немедленно),
образец — `tools/prove-blocking-rules.ps1`. Файл `.ps1` с кириллицей обязан
иметь BOM, иначе Windows PowerShell 5.1 читает его как ANSI и падает
непонятной синтаксической ошибкой.

**Контрольный красный обязателен.** Прежде чем поверить зелёному, надо убедиться,
что та же оснастка умеет давать красный: модуль с вызовом несуществующей
процедуры даёт код 101. Без этого шага замер доказывает не отсутствие проверки,
а собственную неработоспособность.

## Что доказано, а что нет

**Доказано:** ни «Проверка конфигурации» всеми пятью тестами, ни `/CheckModules`
не видят содержимого строкового литерала. Текст запроса, собираемый в коде,
для штатных ворот качества не существует.

**Не доказано:** что офлайн-проверки запроса не существует вовсе. Прогон
проверял штатные пакетные проверки конфигуратора, а не всякий мыслимый
инструмент — например, средства EDT и сторонние проверяльщики синтаксиса
здесь не рассматривались. Формулировка в навыке ограничена тем, что проверено.

## Следствие шире раздела запросов

Слепое пятно не про запросы, а про **строковые литералы вообще**. В ту же
щель проваливаются тексты динамических списков, собираемые в коде, и всё,
что уходит в `Выполнить()`.

Отсюда требование к будущему разделу `1c-quality-gates`: пять зелёных тестов
«Проверки конфигурации» обязаны быть названы тем, что они есть — проверкой
кода, а не проверкой того, что этот код делает с базой. Иначе зелёный ответ
прочитается как «проверено», а проверено ровно то, что вокруг литерала.

Это же объясняет, почему у раздела `1c-queries` проверяльщика нет и не может
быть в том виде, в каком он есть у `1c-build-and-db`: там проверяется состав
команды по документированному перечню ключей, здесь проверять пришлось бы
смысл запроса на данных, которых у агента нет.

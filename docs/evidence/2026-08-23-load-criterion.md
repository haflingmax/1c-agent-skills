# Критерий успеха загрузки конфигурации: прогон и его границы

Находка M-1 финального ревью. Набор в двух местах —
`skills/1c-build-and-db/SKILL.md` и `references/load-configuration.md` —
объявлял доказательством загрузки: «повторный `/DumpCfg` побайтно совпадает
с загружаемым файлом». Отчёт задачи 4 закрыл пункт как «подтверждено,
починено», но подтверждено было прежнее утверждение, а новое прогоном
не проверялось.

## Прогон 23.08.2026

Платформа `C:/Program Files/1cv8/8.3.27.2325/bin/1cv8.exe`, база
`D:/1C/base/trade` — файловая, одноразовая. Каждый запуск через
`Start-Process -Wait`: `1cv8.exe` собран как оконное приложение и без
ожидания возвращает управление немедленно, ничего не создав.

| Шаг | Команда (хвост `/DisableStartupDialogs /Out …` опущен) | Код | Результат |
|---|---|---|---|
| 1 | `DESIGNER /F <база> /DumpCfg <w>\a.cf` | 0 | `a.cf`, 75 395 байт, SHA256 `773C56E8…C88D70F7` |
| 2 | `DESIGNER /F <база> /LoadCfg <w>\a.cf … /DumpResult <w>\load-result.txt` | 0 | журнал: «Загрузка конфигурации успешно завершена», `DumpResult` = 0 |
| 3 | `DESIGNER /F <база> /DumpCfg <w>\b.cf` | 0 | `b.cf`, 75 395 байт, SHA256 `773C56E8…C88D70F7` |

Хэши шагов 1 и 3 совпали полностью:
`773C56E8E8C2609683B772FE8AF520296E3BBBDDFD7BA0F4D9E7B087C88D70F7`.

**Вывод: для cf, выгруженного тем же релизом платформы, критерий верен.**
Это тот же результат, что получил рецензент, — прогон повторён независимо,
а не переписан из находки.

Обратите внимание, что код возврата 0 и `DumpResult` = 0 здесь ничего не
доказывают сами по себе: они те же и у случаев, которые
`docs/evidence/2026-08-22-blocking-rules.md` показывает как тихую порчу
(выдуманный ключ дал код 0, «Сохранение конфигурации успешно завершено»
и отсутствие файла по указанному пути). Доказывает совпадение хэшей.

## Чего этот прогон НЕ доказывает

Критерий был записан без оговорки — как будто побайтное совпадение обязано
получаться всегда. Прогон покрывает только **идемпотентный** случай: выгрузили
этим же релизом, тут же загрузили обратно.

cf, пришедший из поставки или собранный другим релизом платформы, побайтно
так сойтись не обязан, и тогда критерий без оговорки объявлял бы провалом
успешную загрузку — то есть блокировал бы законную работу.

**Прогон на чужом cf не сделан, и вот почему.** На машине установлен ровно
один релиз платформы:

```
> Get-ChildItem 'C:\Program Files\1cv8' -Directory | Select-Object -ExpandProperty Name
8.3.27.2325
common
conf
```

Второго релиза, которым можно было бы собрать «чужой» cf, здесь нет, а cf
из поставки типовой конфигурации в репозитории не лежит и лежать не может.
Досдать этот прогон нечем — поэтому взят первый из двух вариантов починки:
**критерий сужен до cf, выгруженного тем же релизом**, а неохваченный случай
назван прямо в тексте набора вместо молчания.

Что считать доказательством загрузки чужого cf — открытый вопрос, а не
умолчание: придумывать критерий без прогона в этом наборе запрещено тем же
правилом, которым запрещена блокировка недоказанного.

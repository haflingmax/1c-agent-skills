## Замысел

Набор навыков для разработки конфигураций 1С:Предприятие 8.3 по исходникам. Публикуется
как маркет-плагин (Claude Code, Codex) и как отдельные навыки для копирования. Работает
в трёх средах: Claude Code, Kilo Code, Codex.

Строится в два приёма: сначала ядро с раскладкой разделов, потом перенос материала из двух
референсных наборов под MIT.

## Принятые решения

Не пересматривать без нового основания.

1. **16 разделов**, не 13. Добавлены `1c-security`, `1c-libraries-bsp`, `1c-localization`.
   Основание — полное дерево v8std: 318 стандартов, из них 212 действующих для 8.3.
2. **Безопасность отделена от прав.** «Настройка прав доступа» (роли, RLS, профили) и
   «Общие вопросы безопасности» (`Выполнить` на сервере, внешний код, пароли, внешние
   ресурсы) — разные задачи разработчика.
3. **Регламентные задания остаются в `1c-client-server`**, хотя ИТС относит их к метаданным:
   стандарты описывают расписание, запуск и ограничения в режиме сервиса, то есть исполнение.
4. **Бухгалтерия, периодические расчёты, бизнес-процессы — в `1c-metadata-objects`**
   (главы 11–13 руководства разработчика). Вопрос об отдельном разделе открывается заново,
   только если при переносе материал туда не влезет.
5. **Раздела «прочие механизмы платформы» не будет.** Главы 20, 22–25, 29, 32 разложены по
   существующим разделам. Общего у них только то, что они не попали в систему стандартов, —
   раздел по такому признаку агент по описанию не выберет.
6. **Три режима работы** набора: А — внутри конвеера superpowers; Б — голый навык на разовой
   задаче; В — операция с платформой без планирования.
7. **superpowers — рекомендация, не зависимость.** Базовый режим — навык сам по себе.
   Никаких жёстких требований в `plugin.json`; ядро не должно предполагать его наличие.
8. **Правила делятся на правила плана и правила реализации.** Основание: решение уровня плана,
   принятое на реализации, даёт заведомо неверный код.
9. **Документация ИТС в набор не попадает.** Корпус (7,5 млн знаков) остаётся локально как
   сырьё. Публикуется только наше изложение, организованное по задачам. Это ответ и по
   соглашению с 1С, и по объёму: корпус в девять раз больше окна контекста.
10. **Четыре слоя подачи справочного материала:** незыблемые правила в ядре (всегда) →
    рецепт задачи (по совпадению) → справочник ключей (по требованию) → проверяльщик-скрипт
    (детерминированно). Предложено и сверено с архитектурой; правки см. в открытых вопросах.

11. **Новых навыков не заводим.** Раскладка остаётся 16 разделов плюс ядро. Основание —
    потолок каталога Codex: 17 навыков уже занимают 73% бюджета, каждый лишний оплачивается
    чужими описаниями. Проекты с отдельным навыком-планировщиком и с тремя навыками-входами
    отвергнуты по этой причине.
12. **Правила плана живут в теле ядра, а не в `references/`.** Основание — Д-9: в Kilo файлы
    навыка недостижимы, а тело доставляется инструментом `skill` и чтения не требует.
    Место есть: ядро ~2,5 тыс. токенов при пределе 5 тыс.
13. **Восьмое правило архитектуры — признак необратимости.** Правило относится к плану, если
    его нарушение нельзя исправить правкой кода: требуется менять структуру данных,
    перезаписывать данные, менять режим совместимости или получать согласие владельца.
    Всё остальное — правила реализации. К этой формулировке независимо сошлись все три проекта.
14. **Описания ужимаются до 180–200 знаков, разделы не укрупняются.** Слияние разделов
    уничтожило бы раскладку по областям знания, сверенную с ИТС по 318 стандартам;
    сжатие формулировок стоит только слов.
15. **Деградация по наблюдаемому признаку, не по среде.** Ветвление на «готовится ли документ
    плана», а не на «установлен ли superpowers». `dependencies` в `plugin.json` не ставим:
    мягкой зависимости в формате нет, а `{"name": "superpowers", "optional": true}` — ловушка,
    проходит проверку молча и оставляет зависимость жёсткой, убивая весь набор при отсутствии
    плагина.

## Ограничения сред

Проверено состязательно, 67 ранних утверждений опровергнуто. Здесь — то, что выстояло.

- **Codex:** каталог навыков урезается по бюджету — 8000 знаков по умолчанию либо 2% окна
  модели. При переполнении описания режутся, навык молча перестаёт выбираться.
- **Claude Code:** тело вызванного навыка входит в разговор и живёт до конца сессии.
- **Подагенты видят навыки.** Стартуют со списком описаний и могут звать `Skill` сами.
  Не наследуется только переписка родителя. Поле `skills:` во фронтматтере подагента
  преднагружает **полное тело** навыка — единственный детерминированный способ доставки.
- **Ссылки на один уровень — рекомендация Anthropic**, не запрет: «Keep references one level
  deep from SKILL.md». Жёстким его сделал наш собственный проверяльщик.
- **Kilo:** навык ищется по точному совпадению с `name` из фронтматтера.
- **Композиция навыков** официального API не имеет. Модель вызывает соседа инструментом
  `Skill` по имени — это её решение, а не контракт.
- **Одновременность разрешена и ожидаема:** навык следует писать как «не единственный».

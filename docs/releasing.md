# Когда двигать версию

Основание — Н-13 (`docs/reviews/2026-08-23-core-review.md`): `.claude-plugin/plugin.json`
несёт `"version"`, и по документации Claude Code это поле перебивает значение из
`marketplace.json`. Для установивших плагин через маркет (`/plugin install`, основной путь
из README) обновление наступает, только когда строка `version` меняется, — сам факт нового
коммита в репозитории на это не влияет. README обещает «Обновления приходят при обновлении
маркета, ставить заново не нужно»; это обещание правда ровно постольку, поскольку версия
двигается в каждом релизном коммите. Не двинули — обещание нарушено молча, никто не заметит
сразу.

Альтернатива, которую называет сама документация Claude Code, — убрать поле `version`
вовсе: тогда для git-источника используется резолвленный commit SHA, и обновление приходит
автоматически при каждом коммите. Решено этот путь не брать сейчас: версия уже используется
как читаемая метка в двух манифестах разом (`.claude-plugin/plugin.json`,
`.codex-plugin/plugin.json`) и годится как опора для будущих каналов stable/latest. Раз
версия остаётся закреплённой, значит остаётся и обязанность её двигать — вручную, до
появления инструмента, который делает это автоматически.

## Правило

**Любой коммит, который меняет поведение плагина для конечного пользователя, обязан поднять
`version` в `.claude-plugin/plugin.json` и в `.codex-plugin/plugin.json` одним и тем же
числом.** Оба манифеста держат один и тот же плагин под разные среды — расхождение версий
между ними само по себе не ломает установку, но лишает версию смысла как метки состояния
набора.

Что считается «меняет поведение»:

- правка любого файла внутри `skills/` — текста навыка, справочника, скрипта проверяльщика;
- правка `README.md` в части установки, состава разделов или обещаний;
- правка манифестов (`.claude-plugin/`, `.codex-plugin/`) — состав ключевых слов,
  `defaultPrompt`, capabilities.

Что НЕ требует поднятия версии:

- правки внутри `docs/`, `tools/`, `tests/`, `.superpowers/` — рабочие материалы репозитория,
  до конечного пользователя плагина не доходят (`skills:` в манифестах указывает только на
  `./skills/`).

`marketplace.json` версии не несёт и её не требует — трогать не нужно.

## Как двигать

Semver, пока не выпущен `1.0.0`: `0.MINOR.PATCH`.

- `PATCH` — точечная починка навыка или скрипта, поведение не расширяется.
- `MINOR` — новый навык, новый раздел справочника, новая проверка в проверяльщике,
  расширение `description`.
- `MAJOR` не применяется до `1.0.0`.

**Новый навык двигает не только версию.** В том же коммите правится строка
«Собран сейчас один навык раздела: …» в
`skills/developing-1c-configurations/SKILL.md`, раздел «Разделы». Это
единственное место, где работающий агент узнаёт состав набора: README лежит вне
`skills/`, а манифест Codex указывает только на `./skills/` — туда агент не
дойдёт; команда `/plugin` есть в Claude Code и отсутствует в Kilo и Codex
(находка I-7 финального ревью, правило «нет привязки к одной среде» —
`references/architecture.md`). Строку сторожит тест
`tests/test_strengths.py::test_core_names_collected_skills_inline`: она обязана
называть ровно те навыки, что лежат в `skills/`.

`.claude-plugin/plugin.json` и `.codex-plugin/plugin.json` правятся вручную, одним и тем же
числом, в том же коммите, что и остальная правка. **Совпадение обеих строк с 23.08.2026
проверяется машиной** — `tools/check-manifests.py`, `check_version()`: разошедшиеся версии
дают ненулевой код (находка I-4 финального ревью; до неё правило было объявлено здесь, но
не проверялось ничем, и 0.2.0 против 0.3.0 проходило с кодом 0).

```
python tools/check-manifests.py
```

Проверяльщик сверяет равенство версий, соответствие semver и отсутствие дубля версии в записи
маркета. Чего он не знает — **отличается ли новая версия от прежней**: это про историю, а не
про состояние дерева. Свериться перед коммитом:

```
git show HEAD:.claude-plugin/plugin.json | grep '"version"'
grep '"version"' .claude-plugin/plugin.json
```

## Раздаточный каталог Codex + VS Code

У набора есть второй канал доставки, версией не управляемый:
`universal-ai-server/scripts/codex-vscode` уезжает пользователю целиком и несёт
навыки **копией**, потому что у получателя не предполагается ни сети, ни доступа
к этому репозиторию. Маркет эту копию не обновляет — её обновляет только запуск:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools\sync-skills-to-codex-vscode.ps1
```

**Зовётся в том же коммите, где правились `skills/`** — рядом с поднятием версии,
по тому же признаку «меняет поведение для конечного пользователя». Скрипт
печатает, что добавилось, изменилось и удалилось; «изменений нет» — законный
ответ, означающий, что копия уже совпадала. Пропущенная синхронизация ничего не
ломает и ничего не печатает: расхождение видно только у получателя, и выглядит
оно как «навыки не те», а не как «копия устарела».

Путь назначения меняется параметром `-Назначение`, если репозитории лежат не
рядом.

# Когда двигать версию

Основание — Н-13 (`docs/reviews/2026-08-23-core-review.md`): `.claude-plugin/plugin.json`
несёт `"version"`, и по документации Claude Code это поле перебивает значение из
`marketplace.json`. Для установивших плагин через маркет (`/plugin install`, основной путь
из README) обновление наступает, только когда строка `version` меняется, — сам факт нового
коммита в репозитории на это не влияет. README обещает «Обновления приходят при обновлении
маркета, ставить заново не нужно»; это обещание правда ровно постольку, поскольку версия
двигается в каждом релизном коммите. Не двинули — обещание нарушено молча, никто не заметит
сразу.

Альтернатива, которую называет сама документация Claude Code, — убрать поле `version`
вовсе: тогда для git-источника используется резолвленный commit SHA, и обновление приходит
автоматически при каждом коммите. Решено этот путь не брать сейчас: версия уже используется
как читаемая метка в трёх манифестах разом (`.claude-plugin/plugin.json`,
`.codex-plugin/plugin.json`) и годится как опора для будущих каналов stable/latest. Раз
версия остаётся закреплённой, значит остаётся и обязанность её двигать — вручную, до
появления инструмента, который делает это автоматически.

## Правило

**Любой коммит, который меняет поведение плагина для конечного пользователя, обязан поднять
`version` в `.claude-plugin/plugin.json` и в `.codex-plugin/plugin.json` одним и тем же
числом.** Оба манифеста держат один и тот же плагин под разные среды — расхождение версий
между ними само по себе не ломает установку, но лишает версию смысла как метки состояния
набора.

Что считается «меняет поведение»:

- правка любого файла внутри `skills/` — текста навыка, справочника, скрипта проверяльщика;
- правка `README.md` в части установки, состава разделов или обещаний;
- правка манифестов (`.claude-plugin/`, `.codex-plugin/`) — состав ключевых слов,
  `defaultPrompt`, capabilities.

Что НЕ требует поднятия версии:

- правки внутри `docs/`, `tools/`, `tests/`, `.superpowers/` — рабочие материалы репозитория,
  до конечного пользователя плагина не доходят (`skills:` в манифестах указывает только на
  `./skills/`).

`marketplace.json` версии не несёт и её не требует — трогать не нужно.

## Как двигать

Semver, пока не выпущен `1.0.0`: `0.MINOR.PATCH`.

- `PATCH` — точечная починка навыка или скрипта, поведение не расширяется.
- `MINOR` — новый навык, новый раздел справочника, новая проверка в проверяльщике,
  расширение `description`.
- `MAJOR` не применяется до `1.0.0`.

Проверки `version` в CI нет: `.claude-plugin/plugin.json` и `.codex-plugin/plugin.json`
правятся вручную, одним и тем же числом, в том же коммите, что и остальная правка. Свериться
перед коммитом:

```
grep -h '"version"' .claude-plugin/plugin.json .codex-plugin/plugin.json
```

Обе строки обязаны совпадать и обязаны отличаться от той, что была до правки.

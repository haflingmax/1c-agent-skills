# Опровержение: 1c-publish-and-operate

**Дата:** 01.09.2026. Шаг 4 конвейера. Один прогон: 289 агентов —
десять читателей по файлам и по три скептика на каждую находку.

## Как устроено

Десять агентов, по одному на файл раздела, читали текст абзац за абзацем
и сверяли каждое утверждение с корпусами ИТС. Каждую находку затем проверяли
**три скептика с разными углами** — источник, формулировка, последствие, —
и каждому было сказано: по умолчанию считать находку опровергнутой, если
не удалось подтвердить её собственным запросом.

Находка засчитывалась выстоявшей при двух голосах из трёх.

| | |
|---|---:|
| находок на десяти файлах | 93 |
| выстояло после трёх скептиков | 79 |
| отпало | 14 |
| **не проверено** (скептик не ответил) | **0** |
| из выстоявших грубых | 18 |
| важных | 36 |
| мелких | 25 |

**Доля отпавших — 15%.**

### Что починили в самом приборе

В разделе «Проверка качества» подсчёт голосов считал молчание скептика
голосом против: агент, упавший на разборе, отнимал у находки голос так же,
как обоснованный отказ. Одна верная находка тогда выпала **без единого голоса
против**.

Здесь у счётчика три корзины вместо двух: «за», «против» и «не проверено».
Строка «не проверено: 0» в таблице выше — не украшение, а условие, при
котором остальным числам вообще можно верить: доля отпавших честна только
тогда, когда все трое ответили.

## Чем болел раздел: ложное отрицание

Классы дефектов по 79 выстоявшим находкам:

| класс | находок |
|---|---:|
| потерянная оговорка | 17 |
| вывод набора, поданный как факт источника | 12 |
| обрыв цитаты или своя проза в «ёлочках» | 10 |
| **ложное отрицание** | **10** |
| приписанный адрес | 8 |
| подмена модальности | 3 |
| склейка двух механизмов | 3 |
| прочее | 16 |

Самый дорогой класс — не самый частый. **Шесть из восемнадцати грубых находок
— это «источник об этом не говорит» там, где источник говорит.** Раздел
утверждал, что в источниках нет:

- процедуры обновления кластера — ей отведена **целая глава** второй книги
  администратора, с пронумерованной «критической секцией»;
- централизованного управления автоудалением версий — оно лежит
  в `1cescmn.cfg`, который источник рекомендует размещать в сети;
- способа резервировать журнал регистрации силами платформы — у него
  отдельный подраздел с командой и форматами;
- средств диагностики слетевшей привязки лицензии — их два: «Журнал поиска
  ключа» и событие `LIC` технологического журнала со значением `binding`;
- готовой процедуры регистрации автономного сервера службой — в главе лежит
  готовый командный файл;
- системы мониторинга кластера — §2.2.12 той же главы 2.

Ни одно из шести не выдумано на пустом месте: каждое родилось из проверки,
которая **искала не там** — в главе, куда тема не попала. Ноль вхождений
в главе есть факт о главе, не о платформе. Это то же самое, чем этот набор
уже болел на шаге 6 предыдущих разделов, и здесь оно вылезло на шаге 4.

## Второй по цене: оговорка, которую снимают

Семнадцать находок — потерянная оговорка, и в шести случаях снятие оговорки
переворачивало смысл:

- «два ключа одной серии — один ключ» верно только **в одном компьютере**;
  по сети лицензии складываются, и источник говорит это тем же параграфом;
- «первая активация выбирает ветку навсегда» верно только
  для **комбинированной** лицензии; у владельца просто многопользовательской
  выбирать нечего;
- «умолчание менеджера лицензий отдаёт половину ключа» верно только
  для ключа на 500: от 300 умолчание отдаёт 250, от 1 000 — четверть;
- «на PostgreSQL разрыв соединения не делает ничего» верно только
  для соединения **с СУБД**; клиентское соединение рвётся независимо от СУБД;
- «`/EraseData` не имеет отдельного барьера» — барьер двойной, и второй
  (монопольный доступ) как раз и защищает рабочий день;
- «монопольный режим и перезапуск сеансов» относятся только к событиям
  «Доступ» и «Отказ в доступе», а не к аудиту прав доступа.

## Класс, которого раньше не было: номер параграфа в двух книгах

Раздел ссылался на «§7.4.11 руководства администратора». Такой параграф
есть **дважды**: в главе 7 «Автономный сервер» это «Публикация информационной
базы», а `/ReduceEventLogSize` живёт в приложении 7 «Параметры командной
строки запуска». Раздел про журнал регистрации соседствует с разделом про
публикацию — читатель, пришедший по номеру, попадал не туда.

Тот же корень у грубой находки про `DefaultVersion`: **один и тот же
параметр с одним и тем же именем в двух разных файлах** — в `*.v8i` он
означает версию последнего запуска, в конфигурационном файле программы
запуска — версию для подбора неполного номера.

Правило отсюда: **номер параграфа без имени книги и без имени параграфа —
не адрес.** Где номер повторяется, теперь стоит имя.

## Что закрыто

Все 79. Восемнадцать грубых — коммитом `705e34b`, остальные 61 — следом.
Ни одна находка не закрыта удалением утверждения: там, где источник говорил
больше, чем думал раздел, текст **вырос** — появились формула
`Количество центральных серверов = Уровень отказоустойчивости+1`, перечень
условий автоудаления версий, разбор разрыва соединения по трём случаям,
диагностика лицензий двумя приборами и прямой запрет источника использовать
`.dt` как резервную копию с четырьмя названными причинами.
